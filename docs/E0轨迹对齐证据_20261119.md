### Δ 的符号呈完美交替：- + - +
```

**这是「两个独立随机初始化、同一分布采样」的教科书特征。**
若数据管道、结构、超参存在任何系统性偏差，Δ 会单调累积或量级到 10⁻²。

| 假设的错误 | 预期 ΔAUC |

| exp/lin 层数设错 | 参数量直接不符（不是 AUC 问题） |
| **实测 ΔAUC** | **3×10⁻⁵ ~ 8×10⁻⁵** |

**与最轻的错误类型相比，实测偏差仍小 100-300 倍。**

## 二、为什么这个证据比最终 AUC 更强

1. **第 1 轮是确定的比较起点**：没有早停介入、没有优化轨迹分岔累积。
   若数据或结构有任何偏差，第 1 轮就会有可见偏离（通常 0.01 以上）。
2. **两个 epoch 的偏差不累积**：ep1 是 −2.6e-5、ep2 是 +7.6e-5，
   **符号相反、量级相当**，这是「同一分布的独立采样」的特征，
   而不是「系统性偏移」。
3. 最终 AUC 受早停在第几轮影响，而**同一 epoch 数的比较不受此影响**。

## 六、一个工具缺陷的教训（runner 自查发现）

`e0_startup_check.py` 第一版把 `n_epochs <= 1` 判成 FAIL。
但「刚跑完第 1 轮」时 `n_epochs == 1` 是**完全正常**的。
真正的 P4 特征是 `end_lines == 0` 或 `mean is None`。

修法：判据改为只查 `end_lines == 0` 与 `mean is None`；`n_epochs == 1` 降级为 info。
同时做了**负向回归**：P4 场景（只有 start 无 end）仍然 `EXIT=1`。

> **这类假阳性的危害**：如果没被真实数据打脸，工具会在每次开跑 5 分钟时误报 FAIL，
> 然后所有人学会忽略它的 FAIL 列表 —— 一个总在报警的警报器等于没有警报器。

## 附：captain 本轮犯的第 4 次同类错误（留痕）

在核对到第 8 轮时，captain 报告「ep7 Δ=−2.2×10⁻⁴、ep8 Δ=−2.3×10⁻⁴，比前 6 轮放大 7.3 倍」，

```

### 根因与教训
前 6 轮逐一从日志核对过，于是 ep7/ep8 **凭记忆填写**，记忆里混进了主日志的数。

> **教训：轨迹类对照必须每次 `sed -n 'Np'` 逐行从源日志抽取，不许凭记忆补。**
> 「前面几轮核过」不能推出「后面几轮不用核」。

这条与「单点拟合 130,416」「GiB 当 GB」「4 轮宣布符号交替」是同一族错误：
**用不足的证据量或错误的证据源，宣布一个确定性结论。**
