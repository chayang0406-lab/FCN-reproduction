# 实验设计决策：效应量分析后必须调整主次（2026-11-18，captain 决策）

> 这份文件解释**为什么改建什么**。不改会发生的事：花 30 小时跑完，得到一个
> 「无法区分改进和噪声」的结果，报告写不出结论。

## 一、问题：我们想改的东西，效应量比噪声还小

论文 Table 4（FCN𝑠𝑝 消融，Criteo）：

| 变体 | Logloss | AUC(%) |
|---|---|---|
| w/o LCN | 0.4362 | 81.58 |
| w/o ECN | 0.4367 | 81.53 |
| **w/o TB（去掉 Tri-BCE）** | 0.4367 | **81.55** |
| **FCN𝑠𝑝（完整）** | 0.4357 | **81.63** |

**Tri-BCE 整个组件的总贡献 = 81.63 − 81.55 = 0.08 个百分点 = 0.0008 AUC。**

而我们要做的是「把 Tri-BCE 的权重方式从硬截断改成软权重」——
只动这个组件里的一个细节，**可预期的效应量只会更小**，大概 0.0002–0.0005。

## 二、用统计算一下需要多少种子才能测出来

配对设计的样本量公式（σ 取保守规划值 0.001，α=0.05，power=0.80）：

| 想分辨的效应 δ | 需要的配对数（配对 t 检验） |
|---|---|
| 0.0005（0.05pp） | **32 对** |
| 0.0008（0.08pp，= Tri-BCE 全部贡献） | **13 对** |
| 0.001（0.10pp） | **8 对** |
| 0.002（0.20pp） | 2 对 |
| 0.003（0.30pp） | 1 对 |

换算成本（按实测 76 分钟/种子）：
- 分辨 0.001 → 8 配对 = 16 次训练 = **20 小时**
- 分辨 0.0008 → 13 配对 = 26 次训练 = **33 小时**
- 分辨 0.0005 → 32 配对 = 64 次训练 = **81 小时**

**结论：如果主改进是 Tri-BCE 软权重，我们大概率测不出来，且成本极高。**

## 三、决策：把「确定性可测」的 LCA 提为主贡献，Tri-BCE 降为辅助

关键洞察：**参数量和推理延迟是确定性测量，没有随机噪声。**
同一个配置跑 1 次，参数个数就是那个数，延迟的测量误差远小于 AUC 的种子波动。

论文关于 LCA 的声称（原文）：
> "reduces the number of parameters by **50%** and inference latency by **23%**"

这两条都是**可以用 n=1 就严格验证的硬指标**，而且我已经发现论文自身有矛盾：

| 对比（论文 Table 5） | 参数 | 延迟 |
|---|---|---|
| ECN → ECN-full | 0.78M → 1.56M（**2.00×**） | 2.85 → 3.62ms（**+27.0%**） |
| FCN𝑝 → FCN𝑝-full | 1.76M → 3.51M（**1.99×**） | 5.11 → 6.54ms（**+28.0%**） |

**论文正文说「约 23%」，但它自己的表算出来是 27~28%。** 这是个真实的可查矛盾。

### 调整后的主次

| 项目 | 性质 | 需要的种子 | 为什么 |
|---|---|---|---|
| **主贡献：LCA 压缩率扫描 r∈{1,1/2,1/4,3/4}** | 参数、延迟**确定性**；AUC 附带 | 每档 1–2（参数/延迟） | 参数量比、延迟比是硬数字，n=1 即可验证论文声称，并指出 23% vs 28% 的出入 |
| **辅助：Tri-BCE 软权重** | AUC，**噪声内** | 8 配对 | 诚实报告；若测不出，就用功率分析解释为什么测不出 |
| **基线 E0** | AUC | 8 | 作为配对基准，同时给出 σ 实测值 |
| 消融 w/o E2L / w/o L2E / w/o TB | AUC，效应较大 | 各 1–2 | 复现论文趋势（这些是「拆掉整个组件」，效应量比微调大） |

## 四、这样调整后，报告的「测试及分析」怎么写反而更强

大多数同学会写「我跑了 X，原文是 Y」。我们能写三层：

**第一层：复现对不对**
E0 相对作者日志（valid 0.815627 / test 0.816145）的偏差，并用实测 σ 判断是否落在噪声内。

**第二层：论文的硬声称能不能复现（这一层最扎实）**
- 参数砍半：验证 1.99×–2.00×，**支持**论文
- 延迟降 23%：实测 27–28%，**与论文正文不符**，但与论文自己的 Table 5 一致 →
  结论是「论文正文的 23% 表述有误，表格数据是对的」。这是真正有价值的发现。

**第三层：我们的改进有没有用（诚实版）**
- 报告 8 配对种子的 ΔAUC、95% 置信区间、p 值
- 若 ΔAUC < σ，明确写「**未观察到可分辨差异**」，并用功率分析说明
  「以当前 σ=0.00X，要分辨 0.001 需要 8 对以上，本次用了 8 对」
- 这比硬说「提升了」可信得多，而且展示了对实验设计的理解

## 五、时间预算（按实测 76 分钟/种子，1.26× 于 4090）

| 实验 | 次数 | 小时 |
|---|---|---|
| E0 基线（8 种子） | 8 | 10.2 |
| E3 改进（8 种子，与 E0 配对同 seed） | 8 | 10.2 |
| E4-A 消融（w/o E2L, w/o L2E, w/o TB，各 2） | 6 | 7.6 |
| E4-B LCA 扫描（r=1, 1/2, 1/4, 3/4，各 1–2） | 6 | 7.6 |
| **合计** | 28 | **约 35.6 小时** |

分 3–4 天晚上跑完，可行。注意：**6 核 CPU 配额下不要并行**，串行反而总时间更短。

## 六、给 runner 的硬约束

1. **配对设计**：E0 和 E3 用**完全相同的种子列表**（如 2025, 2026, ..., 2032），
   这样种子效应可以相消，把 σ 从「独立」降到「配对」，需要样本量减半。
2. 每个 run 记录：seed、valid AUC、test AUC、logloss、参数量、实际耗时、epoch 数。
3. 参数量必须用 `tools/param_formula.py` 独立核对，对不上就停下来查。
4. **测延迟时必须 warmup**（至少 20 个 batch），否则测到的是 JIT 编译时间。
5. 延迟测量用 test 集固定 batch_size（作者用 16384），重复 3 次取中位数。

## 七、这个决策的代价（要如实承认）

- LCA 扫描的 AUC 部分依然在噪声里，所以**不能声称「某个压缩率更好」**，
  只能声称「参数量和延迟随压缩率的变化规律」+「AUC 未见可分辨差异」。
- Tri-BCE 软权重即使无效，也不是失败——它给了我们一个真实的「效应量低于可测分辨率」
  的案例，配合功率分析是一个完整、诚实、有方法论价值的结论。
- 如果 **8 配对后 ΔAUC 仍 < σ**，报告结论就写成「未观察到可分辨差异」，
  并明确这不是「证明无效」，而是「本实验条件下分辨率不足」。这个区分很重要，
  学术上叫「absence of evidence ≠ evidence of absence」。
