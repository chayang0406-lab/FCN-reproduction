## 零、两件必须先知道的事（否则数据白跑）

### ⚠️ ① 仓库里**没有 `r` 这个配置项**，压缩率是硬编码的

```
src/FCNv2.py L132: self.w.append(nn.Linear(input_dim, input_dim // 2, bias=False))
src/FCNv2.py L136: self.gamma.append(nn.Parameter(torch.ones(input_dim // 2)))
src/FCNv2.py L191/195: 另一个子网，同样 // 2
src/FCNv1.py L129/L182、src/ECN.py L101：同样 // 2
src/ECN.py  L154: input_dim // (2 ** self.max_i)   ← PyramidalExponentialCrossNetwork，另一套递减方案
```

`// 2` 是**字面量**，不是变量。共 7 处硬编码（清单见 `e4b_r_feasibility.json` 的 `hardcoded_sites`）。

> 顺带发现：`ECN.py` 里另有一个类 `PyramidalExponentialCrossNetwork`（L136–L175），
> 它用 `input_dim // (2 ** max_i)` 做**逐层递减**的宽度，而不是固定 1/2。
> 这是仓库里唯一「rank 会随层变化」的实现，但它**没有被 FCNv2 使用**，
> 且与论文式 (6) 的 LCA 不是同一机制。**E4-B 不要用它** —— 若误用，参数量会与本模板全部对不上。

| r | 当前状态 | 要做的事 |
|---|---|---|
| **1/2**（论文 LCA） | ✅ **原生支持**，当前代码就是这个 | 直接跑 |
| **1**（论文 `-full`） | ⚠️ 需换代码路径 | 见 ② |
| **1/4、3/4** | ❌ **不支持** | 必须改代码 + 定维度恢复策略 |

### ⚠️ ② r=1 不能代入 LCA 公式 —— 差 1,248 个参数

论文的 `-full` 是「全秩、**去掉 γ/β**」：

| 算法 | 单层参数 | 值 |
|---|---|---|
| (a) 沿用 LCA 公式取 r=1（保留 γ/β） | d·d + 2d + d | 391,248 |
| **(b) 真全秩（去掉 γ/β）** | d·d + d | **390,000** |

**论文反解证实是 (b)**：ECN-full 4 层 = 4×390,000 + 625 = **1,560,625 = 1.56M** ✅
（若用 (a) 则是 4×391,248+625=1,565,617，与论文的 1.56M 不符。）

→ **r=1 必须走独立的「全秩无 γ/β」代码路径**，不能当作 r=1/2 的连续外推。

### ⚠️ ③ 一个会致命的数值陷阱

```
r=1/2 的「双子网」非嵌入 = 3,528,098
r=1   的「单子网」非嵌入 = 3,510,625
两者只差 17,473（0.50%）
```

**如果把口径混填，会得出「r=1 比 r=1/2 参数还少」的荒谬结论。**
所以模板里**参数量必须三列并列**，永不混用。

## 一、行的维度（4 档 r）

| r | k = round(d·r) | 2k vs d | 维度恢复 | 论文对应 | 性质 |
|---|---|---|---|---|---|
| **1/2** | 312 | **2k = 624 = d** ✅ | **原生 concat**，无需额外操作 | **FCN𝑝（1.76M）** | 复现验证点 |
| **1/4** | 156 | 312 ≠ 624 | ⚠️ 需 pad / 循环重复 2 次 / 额外投影 | 无 | **我们的扩展** |
| **3/4** | 468 | 936 ≠ 624 | ⚠️ 需截断 / 投影降维 | 无 | **我们的扩展** |
| **1** | 624 | 1248 ≠ 624 | 全秩层，**不含 γ/β** | **FCN𝑝-full（3.51M）** | 复现验证点 |

> **为什么只有 r=1/2 能原生工作**：LCA 用 `concat[H_1, H_2]` 从 d·r 复原维度，
> 而残差项 `x` 是 d 维，所以必须 `2·d·r = d` → `r = 1/2`。
> 这是论文设计的**结构性约束**，不是实现疏忽。要在 r≠1/2 时复原维度，必须引入论文没有的操作。

**因此 E4-B 的四个点严格来说不是「同一族模型的连续扫描」**：
两端（1/2、1）是论文原版，中间三点（1/4、3/4）是**我们自定义的扩展**，必须如此声明。

## 二、固定配置（写死以便复现）

> ## ⚠️⚠️ E4-B 用 9 层，E0 基线用 5 层 —— 两者不可混比
>
> | 实验 | 配置 | 每子网层数 | 日志 Total | 用途 |
> |---|---|---|---|---|
> | **E0 基线** | `exp_num_layers=4, lin_num_layers=1` | **5** | **16,532,562** | 复现作者 HEAD 日志（valid 0.815627 / test 0.816145） |
> | **E4-B** | `exp_num_layers=4, lin_num_layers=5` | **9** | 18,100,050（r=1/2） | 对齐论文 Table 5 的 1.76M / 3.51M |
>
> **E4-B 必须用 9 层**才能对上论文 Table 5（论文 FCN𝑝 最优即 4 ECN + 5 LCN）。
> **E0 是 5 层**，它的 16,532,562 与论文的 1.76M **不是同一配置**，绝不可放在一起比。
>
> 写作时最容易犯的错：把 E0 的 16,532,562 拿去和论文 1.76M 比，然后得出"差 9 倍"的荒谬结论。
> 正确关系是：E0（5 层，双子网，含 embedding）↔ 与作者日志 `_016` 比；
> E4-B（9 层，单子网）↔ 与论文 Table 5 比。**两套对照各走各的，不交叉。**

与论文 FCN𝑝 最优配置一致（**9 层**）：

| 项 | 值 |
|---|---|
| dataset | Criteo_x4 |
| 字段数 | 39 |
| `embedding_dim` | 16 |
| **d = 字段数 × embedding_dim** | **624** |
| #Features（vocab 求和） | 910,747 |
| embedding 参数 | 910,747 × 16 = **14,571,952** |
| `exp_num_layers` | **4** |
| `lin_num_layers` | **5** |
| 每子网层数 | 4 + 5 = **9** |
| 末端 fc | d + 1 = **625** |
| batch_size | 8192 |
| lr | 0.001（论文原始；注意作者日志里会自动降到 1e-4 才出最佳，见下） |

> 注：作者日志显示 lr 在第 16 轮被 `ReduceLROnPlateau` 降到 1e-4 后 AUC 才跳到 0.8152+。
> 若我们改动了 scheduler，必须记录，否则与作者日志不可比。

## 三、参数量：三列并列（**这是本表最重要的一节**）

论文 Table 5 用「**单子网非嵌入**」口径；作者日志用「**双子网 + embedding**」口径。
两者差**精确 2.000×**（口径定义使然，非舍入）且可精确换算：

```
论文 Params（单子网非嵌入） = 每子网层数 × 单层参数 + fc
日志 Total              = 2 × 论文 Params + embedding 参数
```

### 3.1 四档 r 的精确参数量（已预填进模板）

| r | 单层参数 | **单子网非嵌入**<br>（= 论文口径） | **双子网非嵌入** | **日志 Total**<br>（= Total number of parameters） | 论文值 | 偏差 |
|---|---|---|---|---|---|---|
| 1/2 | 195,936 | **1,764,049** | 3,528,098 | 18,100,050 | **1.76M** | +0.23% |
| 1/4 | 98,280 | 885,145 | 1,770,290 | 16,342,242 | — | — |
| 3/4 | 293,592 | 2,642,953 | 5,285,906 | 19,857,858 | — | — |
| **1** | **390,000** | **3,510,625** | 7,021,250 | 21,593,202 | **3.51M** | +0.018% |

**LCA vs 全秩 的参数比 = 3,510,625 / 1,764,049 = 1.9901（不是 2.00）**

> 为什么不是正好 2：全秩单层 = d·d + d，LCA 单层 = d·(d/2) + 2·(d/2) + d。
> 两者的 `+d`（bias b）无法与 γ/β 项完全约掉，故比值略小于 2。
> 论文印两位小数：0.78→1.56 舍入成 2.00，1.76→3.51 则是 1.99。
> **报告写「约减半」可以，写「精确 2.00×」不行。**

### 3.2 三条已通过核对的关键断言

| 断言 | 结果 |
|---|---|
| r=1/2 单子网非嵌入 = 论文 FCN𝑝 1.76M | ✅ 偏差 0.23% |
| r=1 单子网非嵌入 = 论文 FCN𝑝-full 3.51M | ✅ 偏差 0.018% |
| r=1/2 单子网 = 日志 `FCNv2_Criteo_020_6dbd8972.log`（exp=4/lin=5）非嵌入 **÷ 2** | ✅ **精确相等**（3,528,098 / 2 = 1,764,049） |
| 论文 ECN-full 反解 = 4×390,000 + 625 | ✅ = 1,560,625 = 1.56M |

> **最后一条是决定性的**：日志的非嵌入参数除以 2 后与论文单子网口径**逐位相同**，
> 这证明「论文 Params = 单子网非嵌入」这个判断不是猜的。

### 3.3 runner 填表时的硬规则

1. **`params_single_subnet_nonembed` 和 `params_double_subnet_nonembed` 必须都填**，
   且满足 `double = 2 × single`（差值应为 0）。
2. `params_total_with_embedding` 必须等于 `single × 2 + 14,571,952`。
3. **与论文对比只许用 `single` 列**（即 `must_match_paper_1x` 那两行）。
4. 若实测参数量与模板预填值不符 → **立即停下**，说明改代码时改错了（不是继续填表）。

### 4.3 延迟为什么必须分两组

论文 **没有交代**延迟的测量口径——「含不含 embedding 查表」这一点从未说明。
Figure 8 的图注只说「只统计非 embedding **参数**」（那是参数量口径，不是延迟口径）。

所以：

- 若我们的「不含 embedding」值接近论文，说明论文测的是纯交叉网络；
- 若「含 embedding」更接近，说明是端到端。
- **两组都报，让数据自己说话**，而不是替论文假定。

**延迟测量协议（论文没给，我们自己定死）**：

1. warmup ≥ 20 个 batch（否则测到 JIT/显存分配开销）
2. 固定 `batch_size`（建议 16384，并在 `notes` 写明实际用的）
3. 重复 ≥ 5 次取**中位数**，同时报 min/max
4. 每次测量前 `torch.cuda.synchronize()`
5. 报告里写明测试集规模与是否含前处理

## 五、「与论文偏差」该怎么归因

`params_deviation_vs_paper_pct` 是预填的理论值（<1%，属论文两位小数的舍入）。
实测后若要填「实测 vs 论文」的偏差，**只能从下面四个原因里归因，且每个都要有证据**：

| # | 可能原因 | 判别方法 | 我们的情况 |
|---|---|---|---|
| 1 | **口径不同**（单/双子网） | 差值是否**精确**为 2.000× | 若精确 2× → 是口径，不是错 |
| 2 | **层数配置不同** | 用层数反解验证 | 论文 FCN𝑝 用 4 ECN+5 LCN（9 层）；若我们改了层数，参数必然不同 |
| 3 | **embedding_dim / 字段数不同** | 检查 d | Criteo d=624；**KKBox 是 128→d=1664，极易搞错**（我曾在此错 98%） |
| 4 | **硬件不同**（延迟） | 只影响延迟，不影响参数量 | 论文 RTX 4090；我们 DCU K500SM_AI |

> **参数量偏差只能由 1/2/3 解释，与硬件无关**——参数量是结构的纯函数。
> 若参数量对不上而 1/2/3 都排除，那就是我们代码改错了，**必须停下查**，不能归因给硬件。

## 六、填完后应该长什么样（预期结论）

基于模板预填值，E4-B 完成后应能给出：

1. **参数量随 r 的变化规律**（确定性，n=1 即可下结论）
   - r=1/2 → 1.76M（单）/ 3.53M（双）；r=1 → 3.51M（单）/ 7.02M（双）
   - **LCA/全秩 参数比 = 3,510,625 / 1,764,049 = 1.9901**，即「约减半」成立（论文声称 ✅）
   - 注意：**不要写成 2.00×**。1.99 才与论文的 3.51/1.76=1.9943 一致。
2. **延迟随 r 的变化**（确定性但依赖硬件/协议）
   - 只能给我们自己条件下的数字 + 95%CI，并注明协议
   - 与论文 23% / Table 5 的 26.74–31.24% 的关系：**报告数值，不作归因**（论文无协议）
3. **AUC 随 r 的变化**（随机，需多种子）
   - 预期：**在噪声内不可分辨**（参照 `docs/参考基准.md` §五，σ=0.001 时需 8 对种子才能分辨 0.001）
   - 若确实测不出差异 → 写「未观察到可分辨差异」，这本身就是支持论文
     「LCA 不牺牲性能」的**诚实证据**（论文说的是 "without sacrificing performance"，
     即"没有显著退化"，与我们"测不出差异"完全相容）
