# `e0_startup_check.py`：E0 开跑 5 分钟的硬断言自检

> runner，2026-11-18。captain 指定的交付物。**退出码就是结论**，不靠人眼看输出。

---

## 一、它检查什么

| # | 检查项 | 失败意味着 |
|---|---|---|
| 1 | `seed_list.json` 存在、位置正确、内容 == `--seeds` | E3 无法复用种子 → **配对设计静默失效** |
| 2 | 每个 run 目录的参数量 == 16,532,562 | 配置没生效 / 数据不对 → **白跑 10 小时** |
| 3 | 计时解析生效（`end_lines > 0`、`n_epochs > 1`、`mean_epoch_seconds is not None`） | P4 复现 → **报告的 s/epoch 凭空消失** |
| 4 | run 目录里的 seed 都在 seed_list 里 | E3 配对会错 |
| 5 | 日志里无 traceback | run 崩了 |

**附加**：单轮耗时合理性告警（< 30s 或 > 600s 时提示，不阻塞）。

---

## 二、为什么第 3 项要做成硬断言

P4 是**静默失效**：`mean_epoch_seconds` 变成 `None`，程序不报错、退出码仍为 0。
如果不做成硬断言，结果就是：

```
跑了 10 小时 → 拿到 8 个种子的 AUC（可用）→ 但「每 epoch 秒数」这一项
拿不到 → 报告「效率分析」章节凭空少一块 → 事后无法补
```

所以脚本对第 3 项做三条独立断言：
- `n_epoch_end_lines == 0` → 说明正则一条都没匹配到（P4b：tqdm 并流把时间戳挤到行中）
- `n_epochs <= 1` → 可能还没跑完一轮，或 P4 复现（用 start 差分）
- `mean_epoch_seconds is None` → 计时不可用


### 负向 5：日志里有 traceback

## 五、用法

```bash
P=/public/home/zengzhicun/user/huanghaijun/projects/course_ctr_fcn_20261118
source /opt/dtk-26.04/env.sh
cd $P

# 开跑后约 5 分钟（等第一个 epoch 跑完）

  --workdir $P \
  --seeds 2025,2026,2027,2028,2029,2030,2031,2032

/usr/local/bin/python3 -X utf8 tools/e0_startup_check.py --workdir $P \
  --seeds 2025,2026,2027,2028,2029,2030,2031,2032 --quiet; echo "EXIT=$?"
```

⚠️ **判退出码不要管道给 `tail`**（`$?` 会变成 tail 的）。

**退出码**：
| 码 | 含义 | 动作 |
|---|---|---|
| 0 | 全部通过 | 让它继续跑 |
| 1 | 有 FAIL | **立刻停，不要等 10 小时** |

## 六、`--workdir` 该给什么（重要）

本脚本会自动搜三处，所以两种写法都能工作：
1. `workdir/runs/seed_list.json` ← driver 默认写法（`--workdir <项目根>`）
2. `workdir/seed_list.json` ← `e0_guard.py` 改后的写法
3. 兜底：`workdir/**/seed_list.json`（3 层内）

但**推荐统一用 `--workdir $P`（项目根）**，这样：
```
$P/runs/seed_list.json
$P/runs/e0_baseline/e0_exp4_lin1_seedXXXX/
$P/runs/e0_summary.json
```
干净、无 `runs/runs/` 嵌套。

若发现 seed_list 是从「兜底搜索」找到的，脚本会直接 FAIL —— 因为那说明位置不符合任何约定，
E3 按约定路径读不到。
