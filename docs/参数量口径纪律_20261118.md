# 参数量口径纪律（2026-11-18，本项目最容易搞错的数字）

> 参数量是本项目**唯一敢用 n=1 严格的验证**的指标，但它有三个不同的口径，
> 混用一次就会得出「论文少报一半参数」这种灾难性误判。这份文件把口径钉死。

## 一、三个口径，必须声明

| 口径 | 含义 | Criteo 数值示例 | 出处 |
|---|---|---|---|
| **总参数** | embedding + 两个子网（E2LCN + L2ECN） | 16,532,562（exp=4/lin=1） | 作者日志 `Total number of parameters` |
| **非嵌入参数（双子网）** | 两个子网的交叉层 + fc，不含 embedding | 1,960,610（exp=4/lin=1） | 需要自己算 |
| **非嵌入参数（单子网）** | 只有一个子网，论文 Table 5 用的就是这个 | 1,764,049（9 层）/ 784,369（4 层） | 论文 Table 5 |

**关系**：
```
总参数 = Σ(vocab_size) × embedding_dim + 2 × 单子网参数
非嵌入(双) = 2 × 非嵌入(单)
```

## 二、闭式公式（已三次独立实测命中）

```
D = 字段数 × embedding_dim = 39 × 16 = 624
每层交叉参数 = D×(D/2) + D/2 + D/2 + D = 195,936
                └─ w(624→312)  └γ(312) └β(312) └b(624)
单子网(exp, lin) = (exp + lin) × 195,936 + (D + 1)     # +1 是 fc 的 bias
总参数 = Σ(vocab_size) × embedding_dim + 2 × 单子网(exp, lin)
```

## 三、⚠️ 作者仓库里有两个不同代码库的日志，不能混用

这是最容易踩的坑。作者仓库 `checkpoints/` 里的日志分两批：

| | 批 A（旧） | 批 B（新 = HEAD） |
|---|---|---|
| 日期 | 2025-05-11 | 2025-05-12~13 |
| 参数名 | `ECN_num_layers` / `LCN_num_layers` | `exp_num_layers` / `lin_num_layers` |
| 每层参数增量 | **49,920** | **391,872**（= 2 × 195,936） |
| checkpoint 路径 | `/root/autodl-tmp/model_zoo/DCNv3/DCNv3_torch/` | 本地 checkpoints |
| 能否用 HEAD 代码复现 | **不能** | 能 |

**批 A 的真实规律（14 份日志 / 13 个配置，残差全 0）**：
```
总参数 = 15,838,674 + 49,920 × (ECN层数 + LCN层数)
```
这是**经验线性律，结构未确定**。旧源码不在本仓库（`git log --all -- src/FCNv2.py` 只有 1 次提交），
且默认路径指向 `DCNv3_torch` 项目，**说明批 A 根本不是 FCN 代码跑的**。
`49,920 = 2 × 40 × 624` 里那个「40」没有自然结构解释，**不编**。

### 一个必须避免的错误算法
```
旧非嵌入 1,566,242 ÷ 195,936（HEAD 单层成本） = 7.994 ≈ 8 层   ← 错！
```
**把旧实现的参数量除以新实现的单层成本，两个不同模型混算，得出的层数毫无意义。**
正确做法：批 A 用 49,920 那套，批 B/HEAD 用 195,936 那套，**两套绝不交叉**。

## 五、与论文 Table 5 对比时的口径换算

论文 Table 5 的 Params 是**单子网**口径。我们的实测是**总参数**。换算：

| 我们要比的东西 | 论文值（单子网） | 我们的等价量（双子网总） |
|---|---|---|
| ECN（4 层，r=1/2） | 0.78M | — |
| ECN-full（r=1） | 1.56M → **2.00×** | — |
| FCN𝑝（4 ECN+5 LCN，r=1/2） | 1.76M | 非嵌入双 = 3,528,098 |
| FCN𝑝-full（r=1） | 3.51M → **1.99×** | — |

**验证证据**：`FCNv2_Criteo_020_6dbd8972.log`（exp=4/lin=5，即 4 ECN+5 LCN 的反向配置）
实测非嵌入 = 3,528,098 = **2 × 1,764,049**，与论文 FCN𝑝 的 1.76M 差值 0。

**报告必须写**：「本文参数量为双子网总计，论文 Table 5 为单子网口径，两者相差 2.00 倍，
比较时已统一换算。」否则会被误判成「论文少报一半参数」。

## 六、方法论纪律（本项目教训固化）

1. **单点拟合一概视为欠定**：用拟合公式下结论，必须在 **≥3 个不同自变量取值**上验证。
   （本项目真实翻车：只看 `Σ层数=6` 一个点，反解出「每层 130,416」，宣布残差归零；
   后来用 14 个点验证，真实斜率是 49,920，错 2.6 倍。）
2. **验证器本身要被验证**：闸门要证明能拦住错误（例如故意用 exp=4/lin=2 建模却期望
   exp=4/lin=1 的参数量，必须报出 +391,872 的差值）。
3. **valid / test 必须分列**：早停是在 valid 上选模型，test 系统性偏高。
   真实反例：某对比 valid 差 −0.000072（变差）而 test 差 +0.000046（变好），**符号相反**。
4. **区分确定性指标与随机性指标**：参数、延迟 → n=1 可严格验证；
   AUC → 必须多种子，报 mean±SD，且用功率分析说明分辨率。
5. **外推必须标注不确定来源**，且不得把外推值写进报告当实测值。
