# 数据画像与必须声明的诚信边界（2026-11-18）

> 这份文件里有三条会直接影响报告可信度的发现。
> 第三条（CTR 25.6% vs 工业 3%）是**必须写进报告**的诚信声明，不写会被判为误导。

## 一、三份数据的 CTR 精确相同——第六个数据正确的证据

| 文件 | 行数 | 正例数 | CTR |
|---|---|---|---|
| train | 36,672,493 | 9,396,350 | **25.6223%** |
| valid | 4,584,062 | 1,174,544 | **25.6223%** |
| test | 4,584,062 | 1,174,544 | **25.6223%** |

**三份 CTR 精确到小数点后 4 位完全相同，且 valid 与 test 的正例数同为 1,174,544。**

这不是巧合，而是 `StratifiedKFold(n_splits=10, shuffle=True, random_state=2018)` 的必然结果：
分层抽样保证每一折的正例比例与全集一致；valid 和 test 又恰好各 4,584,062 行（同一折大小），
所以正例数必然相同。

**为什么这是好证据**：
1. 它**不依赖哈希**（md5 只能证明"文件没坏"，不能证明"按论文口径切的"）
2. 它直接验证了**切分方式**与论文一致（论文用的是同一套 reczoo 预处理）
3. 如果切分方式不同（比如随机切而非分层切），三份 CTR 会有可见差异

→ 报告「测试及分析」可以写：「三份数据的正例比例精确相等（25.6223%），
与 `StratifiedKFold` 分层抽样一致，可作为数据切分口径与原文相符的直接证据。」

## 二、⚠️ 必须声明的诚信边界：CTR ≈ 25.6%，不是工业真实点击率

**真实 Criteo Display Advertising Challenge 数据集的点击率约 3%。**
`reczoo/Criteo_x4` 是**负样本下采样**（negative downsampling）后的**平衡数据集**，
把 CTR 抬到了 25.6%。

### 为什么这条必须写进报告
如果不声明，会犯两个错：
1. **把 AUC 0.8157 误读成「工业可用水平」**。真实工业场景下 CTR 约 3%，
   同样模型在原始分布上的 AUC 会不同（下采样会**抬高** AUC，因为负样本变少了）。
2. **违反课程要求的「完整、准确」**。数据是被处理过的，不说明等于隐瞒前提。

### 建议的表述
> 本文使用的 `reczoo/Criteo_x4` 是经过负样本下采样的平衡版本，正例比例 25.6223%；
> 原始 Criteo 广告点击数据的点击率约为 3%。因此本文报告的 AUC 与 LogLoss
> **仅在下采样分布下可比**，不能直接外推到工业原始分布。
> 该下采样是 reczoo 官方预处理的一部分，论文与作者代码同样使用该版本，故复现对照有效。

这段话做了三件事：承认限制、说明来源、说明为什么复现对照仍然成立。
**这比装作没这回事强得多，也是「与原文工作对比分析」的加分内容。**

## 三、原始基数 vs 过滤后 vocab_size（口径绝不能混）

data 用 100 万行抽样算出 C3 的**原始基数 348,299**，而作者全量**过滤后 vocab 是 157,339**。

| 口径 | 含义 | C3 数值 |
|---|---|---|
| 原始基数 | CSV 里出现过多少种不同取值 | 348,299（1M 抽样估算） |
| **过滤后 vocab_size** | 出现次数 ≥ `min_categr_count=10` 的取值数 + 2 | **157,339**（作者日志） |

**两者绝不能填进同一列。** 报告里凡提 vocab，必须写「过滤后（min_categr_count=10）」。
论文 Table 2 的 `#Features = 910,747` 也是**过滤后**口径。

## 四、独立佐证：论文正文的 `⌊log2 x⌋` 是错的

data 用独立方法（1M 抽样 + 理论上界）得出与我一致的结论：

| 规则 | 在 x ∈ [0, 10⁶] 时的取值上界 | 能否产出 I1 = 44 |
|---|---|---|
| `⌊log2 x⌋`（论文正文） | **19** | **不可能** |
| `⌊(ln x)²⌋`（作者代码） | **190** | 可以 |

两条独立路径（我用 13 字段逐个反解、data 用理论上界）得出同一结论，
**这个判定可以说相当稳了**（唯一例外是 I10，它的需求量恰好落在 log2 能力边界上，无法判别）。
