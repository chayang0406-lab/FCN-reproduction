# 开跑前最后一份检查：`--workdir` 路径错位（会导致 8 个种子白跑）

> runner，2026-11-18。这是**开跑前必须知道的一条**：captain 给的命令里
> `--workdir $P/runs` 会让 driver 与 guard 对 `seed_list.json` 的位置理解不一致。
>
> 后果不是崩溃，而是：**`seed_list.json` 生成在没人找的地方，E3 无法复用种子列表，
> 配对设计静默失效，而所有工具都显示「正常」。**

---

## 一、问题：两处代码对 `--workdir` 的语义不同

| 文件 | 行 | 代码 | 含义 |
|---|---|---|---|
| `run_e0_baseline_v2.py` | 121 | `os.path.join(args.workdir, "runs", "seed_list.json")` | workdir **/runs**/seed_list.json |
| `e0_guard.py` | 110 | `os.path.join(args.workdir, "seed_list.json")` | workdir / seed_list.json |

**两者差一层 `runs/`。**

而 `e0_baseline` 目录两边的理解是**一致**的：
- driver 第 118 行：`os.path.join(args.workdir, "runs", "e0_baseline")`
- guard 第 129 行：`os.path.join(args.workdir, "runs", "e0_baseline")`

所以**只有 `seed_list.json` 这一处错位**，其它都对。

---

## 二、实测：`seed_list` 的检查永远报 warn

`--workdir /tmp/wf` 跑完一个 run 后：

```
driver 实际写出：
  /tmp/wf/runs/e0_summary.json
  /tmp/wf/runs/seed_list.json

guard 找的是：
  seed_list : /tmp/wf/seed_list.json      ← 找不到
  e0_baseline: /tmp/wf/runs/e0_baseline   ← 找得到（一致）
```

实测输出：
```
[warn] 还没生成 seed_list.json（首次运行会生成）
```

**这个 warn 会永久存在**，无论 E0 跑了多少个种子。因此：

| 现象 | 真实情况 | 危害 |
|---|---|---|
| precheck 说「还没生成 seed_list.json」 | 其实已经生成了，只是不在那 | 人会以为「首次运行会生成」，于是忽略 → **永远不会去核对种子列表** |
| E3 想读 `$P/runs/seed_list.json` | 文件在 `$P/runs/runs/seed_list.json` | E3 读不到 → 用默认种子或手写种子 → **配对设计静默失效** |

**这就是最坏的一类失败**：全部显示绿色，但配对设计已经不在。

---

## 三、captain 原命令的实际落盘位置

原命令：
```bash
--workdir $P/runs
```

driver 内部再拼 `runs/`，所以实际落盘是：

```
$P/runs/runs/seed_list.json          ← 注意两个 runs
$P/runs/runs/e0_baseline/e0_exp4_lin1_seed2025/
$P/runs/runs/e0_summary.json
```

而 `e0_guard.py --summarize --workdir $P/runs` 找的是 `$P/runs/runs/e0_baseline` —— **这个是一致的**，
所以 summarize 能正常工作。**唯一坏掉的是 seed_list。**

---

## 四、三种修法（任选，我建议 ①）

### ① 开跑时 `--workdir` 给项目根，并显式确认 seed_list 位置（不改代码，最省事）

```bash
--workdir $P          # 注意：不是 $P/runs
```

此时：
- `seed_list.json` → `$P/runs/seed_list.json`
- `e0_baseline/` → `$P/runs/e0_baseline/`

但 guard 仍读 `$P/seed_list.json`（因为它只拼一层）。**所以 guard 的 seed_list 检查仍会 warn。**

→ **实操建议**：接受 guard 的这条 warn 永远存在，改用**显式路径核对**：

```bash
# 开跑后 5 分钟，人工确认（这是唯一可靠的判断）
cat $P/runs/seed_list.json
```

### ② 改 guard 一行，让它读 `workdir/runs/seed_list.json`（推荐给 captain）

```python
# e0_guard.py:110 原
sl = os.path.join(args.workdir, "seed_list.json")
# 改为
sl = os.path.join(args.workdir, "runs", "seed_list.json")
```

这样两边彻底对齐，precheck 才有意义。

### ③ 开跑后做一次软链接（零改代码，立刻可用）

```bash
ln -sf $P/runs/runs/seed_list.json $P/runs/seed_list.json   # 若用原命令
# 或用 ① 的 workdir 时：
ln -sf $P/runs/seed_list.json $P/seed_list.json
```

## 七、一个已修正的自身错误（留痕）

我最初判断 `--workdir $P/runs` 会导致 `e0_baseline` 也错位，实测证明**只有 seed_list 错位**，
`e0_baseline` 两边一致。上面是在纠正后的结论，不是初稿。

原因：我第一次只看了 driver 第 118 行（`workdir/runs/e0_baseline`）与
guard 第 129 行（`workdir/runs/e0_baseline`），**两者其实一样**；
真正不一致的是 guard 第 110 行（`workdir/seed_list.json`）。

**教训**：说「A 和 B 不一致」之前，要把两边**各自的行号**都列出来核对，
而不是凭印象。我在本文第一节做了这件事。
