## 一、上传命令（一条搞定）

```bash
# 本地路径
cd "D:\中南大学\数据挖掘"

# 逐个上传（base64 方式，实测最稳；避免 scp 因中文路径/权限问题失败）
$P = "/public/home/zengzhicun/user/huanghaijun/projects/course_ctr_fcn_20261118"
$keys = @(
  "recover_after_outage.py","run_e4b.py","verify_e4a_results.py",
  "run_e0_baseline_v2.py","patch_e0_driver.py","e0_startup_check.py",
  "verify_h5_dataset.py","verify_improved_configs.py","paired_analysis.py",
  "run_improved_driver.py","author_baseline.py","make_synthetic_full_vocab.py",
  "verify_e0_report_numbers.py"
)
foreach ($k in $keys) {
  $b64 = [Convert]::ToBase64String([System.IO.File]::ReadAllBytes("tools\$k"))
  $b64 | Set-Content "$env:TEMP\up.b64" -Encoding ascii -NoNewline
  Get-Content "$env:TEMP\up.b64" -Raw | ssh -o BatchMode=yes -p 10188 root@ksai.scnet.cn "base64 -d > $P/tools/$k 2>/dev/null; md5sum $P/tools/$k"
  Write-Host "$k -> $((Get-FileHash "tools\$k" -Algorithm MD5).Hash)  (local)"
}
```

**校验方式**：每行输出两个 md5（远程 + 本地），**必须相同**。
这是本项目一贯做法——上传后立即核对 md5，不用「应该传对了」判断。

## 五、这些工具的共同设计原则（供报告附录引用）

**每一个都至少有一个「来自真实失败历史」的负向测试**：

| 工具 | 负向用例 | 来源 |
|---|---|---|
| `run_e0_baseline_v2` | Σvocab=2359 → MISMATCH | 真实子集测试 |
| `verify_improved_configs` | `abl_exp0` 改 4/1、`tri_mode` 改回 hard | 真实盲区 |
| `e0_startup_check` | 5 个（未启动/P4/参数量/traceback/seed 不符）| 真实踩过的坑 |
| `verify_e4a_results` | 参数量对但层数 4/1≠5/0 | 真实盲区 |
| `paired_analysis` | 配对性破坏 / 零效应 / 数学正确性 | 真实场景 |
| `verify_h5_dataset` | vocab=2359 → 逐字段 FAIL | 真实反向用例 |
| `run_e4b` | 公式 vs 论文差值非 0 → 拒绝出表 | 结构推导自证 |
| `recover_after_outage` | 4 场景（0/1/2/3 退出码）| 真实故障场景 |
| `verify_e0_report_numbers` | 期望值硬编码，漂移即 FAIL | 防报告与数据脱节 |

**共同点：负向用例都来自「已经真实发生过」的失败，不是想象的失败。**
