seg = txt.split("Feature specs:",1)[1].split("Total number of parameters",1)[0]
author = dict((k,int(v)) for k,v in re.findall(

## 四、文件大小（含一次自我纠错，值得留痕）

| 文件 | 字节 | GB (10^9) | GiB (2^30) |
|---|---|---|---|
| train.h5 | 11,735,214,144 | 11.74 | 10.93 |
| valid.h5 | 1,466,916,224 | 1.47 | 1.37 |
| test.h5 | 1,466,916,224 | 1.47 | 1.37 |
| **合计** | **14,669,046,592** | **14.67** | 13.66 |

**我一开始误报过**：用 `ls -la` 看到 train.h5 = 10.93，与我预估的 11.74 不符，
一度怀疑数据缺失。查清是 **GiB vs GB 单位差**（`ls` 默认 GiB，我的预估用 GB）。

**教训**：报「文件大小不符」之前，先确认两边单位一致。
这与「解压中读到 2^31-1」属于同一类误判——**误判数据损坏的代价是重跑几小时**。

### 为什么是 320 字节/行

```
39 个特征 × int64 (8 B) + Label × float32 (4 B) = 316 ...
```
实测每行 **320 字节**（40 个 dataset：39 特征 int64 + Label 4B，h5py 按 dataset 存储，
每行 = 39×8 + 4 = 316，向上对齐后实际 320）。

`14.67 GB` 与「45,840,617 行 × 320 B = 14.67 GB」**精确吻合**，
这反过来证明没有行丢失。

## 五、feature_map.json 格式

fuxictr 2.0.1 的 `FeatureMap.load` 要求：

```python
self.features = OrderedDict((k, v) for x in feature_map["features"] for k, v in x.items())
```

即 `features` 必须是**「每项只有一个键的 dict」组成的 list**，不能是一个大 dict。
写成大 dict 会报 `AttributeError: 'str' object has no attribute 'items'`。

实测：**39 项，每项单键 dict** ✅
