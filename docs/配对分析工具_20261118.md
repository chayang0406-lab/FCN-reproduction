> runner，2026-11-18。E0 的 `--v2` 与改进实验的 4 维闸门都已就绪，

## 一、发现：配对设计目前「无工具可执行」

项目纪律（`docs/实验设计决策_效应量与主次调整_20261118.md` §六第 1 条）写着：

> **配对设计**：E0 和 E3 用**完全相同的种子列表**，这样种子效应可以相消，
> 把 σ 从「独立」降到「配对」，需要样本量减半。

但实测发现三个缺口：

| 缺口 | 证据 |
|---|---|
| `seed_list.json` 只被**写**，无人**读** | `grep -rl seed_list` 只命中 E0 三个变体 + `e0_guard.py`，都是写入方 |
| `run_improved.py` 只有 `--seed`（单值） | 没有 `--seeds`（从文件读） |
| 没有任何配对统计工具 | `ls tools/ | grep -E "pair\|t_test\|stats"` → 空 |

**这意味着这条纪律全靠人记。** 一旦 E3 用了不同种子（哪怕只差一个）：
- 配对相消失效 → 退化成独立两样本
- 所需样本量从 8 翻到 16（而实际只跑 8 个）
- **报告里完全看不出来** —— 会写成「ΔAUC=0.0003，p=0.4，未观察到提升」

## 二、解法：`tools/paired_analysis.py`

做两件事：**先硬校验配对性，再做统计**。

### 2.1 配对性硬校验（这是核心价值）

若给了 `--seed-list`，工具会检查两组的有效结果是否**覆盖全部声明种子**。
缺任何一个就 `exit 2`，并明确指出缺哪些：

```
!! 配对性破坏：seed_list 声明了 6 个种子，但有效结果不全
   改进组缺：[2030]

配对设计的前提是「同一个种子两组都有」。缺一个就无法相减，
退化成独立样本后，所需样本量约翻倍（16 → 8 的前提不再成立）。
请补跑缺失种子，或用 --seed-list 指定一个更小的公共子集（并记录原因）。
```

也支持参数量闸门联动：某 run 参数量不对会被 `EXCLUDED`，然后触发同一个配对性检查。

### 2.2 统计口径（写清为什么这么算）

| 量 | 含义 | 为什么重要 |
|---|---|---|
| `ΔAUC 均值` | 逐 seed 相减后取均值 | 种子效应被相消 |
| **`σ_Δ`** | **差值**的标准差 | **决定能否测出改进的量，不是 σ** |
| `95% CI` | 用 t 临界值算 | 区间是否跨 0 才是判据 |
| 配对 t 检验 | t、p、df | 参数法 |
| Wilcoxon 符号秩 | W、p | 非参数法，不假设正态 |
| `改进赢的种子数` | 6/6 这种 | 最直观；6/6 全赢比 p 值更容易解释 |
| **`δ_min`** | 本次设计的分辨率 | `|Δ| < δ_min` 时只能写「未观察到可分辨差异」 |
| `n_needed` | 分辨 0.001 需要几对 | 给下一轮排期用 |

**δ_min 公式**：`(t_{0.975} + t_{0.80}) × σ_Δ / √n = 2.8016 × σ_Δ / √n`
人话：σ_Δ 是「配对后的抖动」，n 是配对个数，抖动除以 √n 就是均值的精度；
再乘 2.8（对应 95% 把握和 80% 检出率的门槛），就是「这次能看出的最小差别」。

### 2.3 关键区分：σ_Δ ≠ σ

- **σ**（E0 测出来的）= 同一配置、不同种子的波动 ≈ 噪声基线
- **σ_Δ**（本工具算的）= 配对**差值**的波动

若种子效应真的共通，σ_Δ 会远小于 σ。**配对设计的收益就体现在这个比值上。**

实测（合成数据，真实效应 +0.0012）：σ=0.0009 但 **σ_Δ=0.000191**，缩小 4.7 倍。
这直接解释了「为什么配对能把需要样本量减半」。

## 三、实测证据

### 3.1 数学正确性（已知答案核对）

```
手工 t=14.142136  实现 t=14.142136  一致=True
delta_min(σ=0.000200, n=8)=0.000198  手算=0.000198
Wilcoxon 全正 4 个 → W=0（正确）
Wilcoxon 对称 4 个 → W=5.0, p=1.0000（正确，不显著）
t 临界值：df=1→12.706, df=7→2.365, df=30→2.042, df>30→1.96
```

### 3.2 端到端 A：正常配对（6 对，真实效应 +0.0012）

```
--- valid AUC（配对，n=6）---
  ΔAUC 均值      : +0.001339
  σ_Δ（差值标准差）: 0.000191
  95% 置信区间    : [+0.001139, +0.001540]
  配对 t 检验    : t=17.172, p≈0.01, df=5
  Wilcoxon 符号秩 : W=0, p≈0.0277
  改进赢的种子数  : 6/6
  本次分辨率 δ_min: 0.000218
  判定（valid）: 达到可分辨
```

**从 6 个种子就测出了 +0.0012 的效应**——因为 σ_Δ 只有 0.000191。
对照：若用独立两样本，σ=0.0009 时分辨 0.0012 需约 14 对。**配对省了一半以上。**

### 3.3 端到端 B：配对性破坏 → exit 2

改进组删掉 `seed2030` → 工具立即拒绝，明确列出 `改进组缺：[2030]`。

### 3.4 端到端 C：参数量错的 run 被排除 → 也触发配对性检查

把 `seed2026` 的参数量改成 `1998354`：
```
    seed 2026  EXCLUDED：参数量 1998354 ≠ 16532562
!! 配对性破坏：seed_list 声明了 6 个种子，但有效结果不全
   改进组缺：[2026]
```

### 3.5 端到端 D：零效应对照组 → 正确结论

```
valid：ΔAUC = -0.000014，**未观察到可分辨差异**（本次 δ_min=0.000192）。
学术表述：absence of evidence ≠ evidence of absence。
⚠️ valid 与 test 的差**符号相反**，不能合并成一个结论，必须分列报告。
```

**这个输出正是项目要的诚实版结论**，而不是硬说「有提升」。

## 四、用法

```bash
P=/public/home/zengzhicun/user/huanghaijun/projects/course_ctr_fcn_20261118
source /opt/dtk-26.04/env.sh
cd $P

# E0 vs E3 配对分析（E0 读 train.log，E3 读 result.json，都支持）
/usr/local/bin/python3 -X utf8 tools/paired_analysis.py \
  --baseline-dir $P/runs/e0_baseline \
  --improved-dir $P/runs/e3_soft \
  --seed-list $P/runs/seed_list.json \
  --expect-params 16532562 \
  --out $P/runs/e3_paired.json \
  --label "Tri-BCE soft(smoothmax)"
```

**退出码**：
| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 正常出统计 | 可用 |
| 2 | 配对性破坏（种子不全） | **补跑缺失种子**，不要硬算 |
| 3 | 有效配对 < 2 | 无法统计 |

目录约定：每个 seed 一个子目录，名字里含 `seed<数字>`（如 `e3_soft_seed2025`），
子目录内放 `result.json`（首选，全精度）或 `train.log`（退回，6 位小数）。

## 五、对排期的实际影响（重要）

原计划「8 配对」，但本工具的公式给出了更精确的答案：

| 若实测 σ_Δ | 分辨 0.001 需配对 | 分辨 0.0005 需配对 |
|---|---|---|
| 0.0002 | **<1**（8 对富余） | 4 对 |
| 0.0005 | 2 对 | 16 对 |
| 0.0010 | 8 对 | 62 对 |
| 0.0020 | 31 对 | 246 对 |

**所以 σ_Δ 的实测值是决定 E3 能不能出结论的唯一关键数字**——
它必须等 E0 与 E3 都跑完才算得出。这也是为什么 E3 必须复用同一份种子列表：
否则 σ_Δ 无法计算，整条统计链断掉。

## 六、一个尚未解决的缺口（如实说明）

`run_improved.py` 没有 `--seeds`（从文件批量读）。当前只能：
```bash
for S in 2025 2026 ...; do
  python3 code/src/run_improved.py ... --seed $S --out runs/e3_soft/e3_soft_seed$S
done
```
**风险**：手写的 `for` 循环若漏掉一个种子、或目录名不带 `seed<N>`，
本工具的配对性检查会拦下（这已经是安全网），但**没有工具保证你写对了循环**。

**建议**：E3 开跑时我在 driver 层包一层，从 `seed_list.json` 读种子遍历，
并在每个 run 结束后立即调 `paired_analysis.py` 的配对性检查。
这样「漏一个种子」会在 5 分钟内被发现，而不是 10 小时后。
