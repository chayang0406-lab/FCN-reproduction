# 官方 run_expid.py 的三个真实缺陷（已实测，必须用修正版）

> 结论：作者仓库的 `run_expid.py` **在 fuxictr 2.0.1 + 我们的环境里跑不起来**。
> 必须在 `tools/run_expid_fixed.py` 里绕开。这不是"环境没配好"，是它本身的代码问题。

## 缺陷 1：导入了不存在的函数（连启动都不行）

```python
from fuxictr.utils import load_config, set_logger, print_to_json, print_to_list, delete_model_files
```

`fuxictr 2.0.1` 的 `utils` 里**没有** `delete_model_files`。实测该模块只有：
```
load_config, load_model_config, load_dataset_config, set_logger,
print_to_json, print_to_list, load_h5
```

报错：
```
ImportError: cannot import name 'delete_model_files' from 'fuxictr.utils'
```

作者可能用的是 fuxictr 的某个中间版本，或本机有别的包覆盖。总之**在标准 2.0.1 上必炸**。

**修法**：删掉 `delete_model_files` 的导入，以及脚本末尾清理模型的调用。

## 缺陷 2：FeatureProcessor 被 KKBox 版覆盖（CSV→h5 必炸）

```python
from fuxictr.preprocess import FeatureProcessor          # 通用版
from fuxictr.datasets.kkbox import FeatureProcessor      # ← 覆盖掉上面
```

`kkbox.FeatureProcessor` 只有 `extract_country_code` / `bucketize_age`，
**没有 `convert_to_bucket`**；而 Criteo 的 13 个 I 字段配置要求它有。

报错：
```
AttributeError: 'FeatureProcessor' object has no attribute 'convert_to_bucket'
```

**作者没踩到**，因为他日志里 `data_format: h5` —— 直接用别人转好的 h5，跳过这一步。

**修法**：`from fuxictr.datasets.criteo import FeatureProcessor`

## 缺陷 3：dataset_config 缺少 `Criteo_x4_10_h5` 这一项

`model_config.yaml` 里 `FCNv2_Criteo` 的 `dataset_id` 是 `Criteo_x4_10_h5`，
但 `dataset_config.yaml` 里**只有 `Criteo_x4_001`（csv 格式）**，没有 h5 版。

报错：
```
RuntimeError: dataset_id=Criteo_x4_10_h5 is not found in config.
```

说明作者本地有一份没提交的 config。

**修法**：从 `Criteo_x4_001` 复制字段定义，改成 `data_format: h5` 并指向
`<data_root>/Criteo_x4_10_h5/{train,valid,test}.h5`。
`tools/run_e0_baseline.py` 里已自动补出（会打印 `[fix] dataset_config 缺 Criteo_x4_10_h5`）。

## 另外两处小问题（无害但应清理）

- `sys.path.append("/home/lhh/code")`：作者本机路径，无意义。
- `import sys` / `import os` 重复出现多次。

## 验证：修正版已端到端跑通

`tools/run_expid_fixed.py` 复制原作者全部逻辑，只修上述三点，实测：

```
退出码 0
valid AUC 0.747421 / test AUC 0.751153（子集数据，数值本身无参考意义）
参数量 2,379,170
```
并且**参数量闸门正确报出 MISMATCH** —— 因为用的是 20 万行子集
（Σvocab=26,160 而非全量的 910,747），期望值 16,532,562 自然对不上。
**闸门按设计工作，这正是它该有的行为。**

## 报告里怎么写这一段（属于「方案实现」的加分项）

> 原仓库的 `run_expid.py` 在 FuxiCTR 2.0.1 下无法直接运行，本文为其修复了三处缺陷：
> (1) 移除了对 fuxictr 2.0.1 中不存在的 `delete_model_files` 的导入；
> (2) 修正了 `FeatureProcessor` 被 KKBox 版本覆盖的问题（Criteo 需要 `convert_to_bucket`）；
> (3) 补齐了 `dataset_config.yaml` 中缺失的 `Criteo_x4_10_h5` 数据集定义
>     （模型配置引用该 ID，但仓库未提供对应定义）。
> 修正后的脚本见附录。

这是**诚实且可核查的工作量**，比声称"直接跑通"可信得多。
