### 3.3 报告要写什么（captain 已定）

**主结论 = 参数量**（确定性、可严格验证、与论文可对照）。

#### ⚠️ 口径必须写清，否则会算错（我核对时发现自己文档里就写错过一次）

自算的交叉网络参数量矩阵（`D=624`，每子网，含末尾 `fc: D→1` 的 `D+1`）：

| 层数 | r=1/2（proj=312，有 γ/β）| r=1（proj=624，全秩无 γ/β）| 比值 |
|---|---|---|---|
| 4 层（ECN）| **784,369** | 1,565,617 | 1.996× |
| **5 层（E0/E3 口径）** | **980,305** | 1,956,865 | 1.996× |
| **9 层（E4-B / 论文 FCN𝑝）** | **1,764,049** | 3,521,857 | 1.996× |

**所以 E4-B（9 层）的比值必须用 9 层那行：**
```
每子网：1,764,049 → 3,521,857 = 1.996×
两子网合计：3,528,098 → 7,042,514  ← 与实测 n_params_cross 一致
模型总参数：18,100,050 → 21,593,202 = +19.3%
```

**❌ 不能写「980,305 → 1,950,625 = 1.99×」** —— 那是 **5 层**口径，
而 E4-B 用的是 9 层。混用会得出「参数只有论文一半」的错误结论
（因为论文 Table 5 的 FCN𝑝 就是 9 层口径 1.76M）。

**这条错误的性质**：两个数都能自算出、比值也都是 1.99×，
**唯一的问题是「用了错误的层数」**。这与今晚反复出现的「基准用错日志」是同一类错误——
**数字都对，但对应错了对象。**

#### 延迟列（captain 决策）
报三项分开（`full_forward` / `embedding_only` / `cross_only`），并注明：
> 因 embedding 查表占参数 88.1% 且计算量近零，交叉网络宽度变化对端到端延迟的
> 影响低于本测量分辨率，故不据此宣称 LCA 的延迟收益。

#### 论文 23% 的矛盾（这是纯文本核算，不依赖我们的硬件）
论文正文说「延迟降约 23%」，但它自己 Table 5 四个比值是：
```
Criteo ECN→ECN-full    (3.62-2.85)/2.85   = +27.02%
Criteo FCNp→FCNp-full  (6.54-5.11)/5.11   = +27.98%
KKBox  ECN→ECN-full    (17.77-13.54)/13.54 = +31.24%
KKBox  FCNp→FCNp-full  (34.41-27.15)/27.15 = +26.74%
```
**没有一个落在 23%±1pp 内。** 这是可查的硬事实。
但**只能说「论文正文与其 Table 5 不一致」，不能说「论文的 23% 是错的」**。

**⚠️ 三条禁止**：
1. ❌ 「论文的 23% 是错的」→ ✅「本实验协议下未复现，且论文正文与其 Table 5 不一致」
2. ❌ 「r 越小延迟越低」→ 数据不支持（实测 r=0.75 最慢，是噪声）
3. ❌ 把我们的 1.4 μs/sample 与论文 5.11 ms 放一起比大小（口径差 3000 倍）

## 四、E3（辅助）详细方案

### 4.1 命令（必须复用 E0 的 seed_list）
```bash
P=/public/home/zengzhicun/user/huanghaijun/projects/course_ctr_fcn_20261118
source /opt/dtk-26.04/env.sh
cd $P

# 前置：确认 seed_list.json 是 8 个种子（E0 跑完后就是这个）
cat $P/runs/seed_list.json

pgrep -af "run_improved_driver" | grep -v pgrep && echo "!!! 已有进程" && exit 1

nohup /usr/local/bin/python3 -X utf8 tools/run_improved_driver.py \
  --configs $P/code/configs --expid FCNv2_C_soft_smoothmax \
  --workdir $P --data-root $P/data \
  --out-subdir e3_soft --epochs 30 \
  --model-root $P/runs/e3_soft_ckpt/ \
  > $P/runs/e3_soft.log 2>&1 &
```

**`run_improved_driver.py` 的设计要点**（这些是它存在的理由）：
- 种子**只从** `runs/seed_list.json` 读，不手写循环 → 「必须复用同一份」由代码强制
- 每个 run 目录名**强制**含 `_seed<N>` → `paired_analysis.py` 一定找得到
- 每个 run 结束**立即**核参数量 + `(exp,lin,tri_mode,lca)` 四维 → 不符当场停

### 4.2 配对分析（E3 跑完后）
```bash
/usr/local/bin/python3 -X utf8 tools/paired_analysis.py \
  --baseline-dir $P/runs/e0_baseline \
  --improved-dir $P/runs/e3_soft \
  --seed-list $P/runs/seed_list.json \
  --expect-params 16532562 \
  --out $P/runs/e3_paired.json \
  --label "Tri-BCE soft(smoothmax)"
```
**退出码 2 = 配对性破坏（种子不全）→ 必须补跑，不能硬算。**

### 4.3 报告口径（诚实版）
- 报 `ΔAUC` 均值、**σ_Δ**（不是 σ）、95% CI、配对 t 与 Wilcoxon
- 若 `|Δ| < δ_min` → 写「**未观察到可分辨差异**」，并用功率分析说明
- **不得写「无效」**：`absence of evidence ≠ evidence of absence`
