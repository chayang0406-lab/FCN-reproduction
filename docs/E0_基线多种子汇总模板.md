## 一、逐种子明细区（`section=detail`，8 行）

每个种子一行。**这些列一个都不能省**——每个都对应一种会犯的错。

| 列 | 单位 | 填法 | 为什么必须 |
|---|---|---|---|
| `seed` | — | 默认 `2025…2032`（8 个） | 配对设计的锚点 |
| `run_id` | — | 如 `E0_s2025` | 与 run 目录对应 |
| **`valid_auc`** | AUC | 最佳 epoch 的 valid AUC | **单独列** |
| `valid_logloss` | logloss | 同上 | 单独列 |
| **`test_auc`** | AUC | best model 的 test AUC | **单独列，绝不与 valid 合并** |
| `test_logloss` | logloss | 同上 | 单独列 |
| `n_params` | 个 | 应为 **16,532,562** | 防跑错配置 |
| `param_check` | OK/MISMATCH | 与 16,532,562 比对 | **MISMATCH 则该 run 作废** |
| `epochs_run` | 轮 | 实际训练轮数（含早停轮） | 判断是否被截断 |
| `best_epoch` | 轮 | 最佳 valid AUC 所在 epoch | 与作者 ep17 对照 |
| `mean_epoch_seconds` | s | 逐轮 wall time 均值（**剔除第 1 轮**） | 与作者 204.365 s 比 |
| `total_train_seconds` | s | 训练总时长 | 与作者 3,883.59 s 比 |
| `status` | ok/fail | 是否成功完成 | 失败的 run 要在 `notes` 写原因 |
| `notes` | text | 任何偏离都记这里 | 审计留痕 |

### 1.1 为什么 valid 与 test 必须严格分列

**实测反例（我们的 E0 对旧实现主日志）**：

| 指标 | E0（新实现 5 层） | 主日志（旧实现） | 差 |
|---|---|---|---|
| valid AUC | 0.815627 | 0.815699 | **−0.000072（变差）** |
| test AUC | 0.816145 | 0.816099 | **+0.000046（变好）** |

**符号相反。** 如果混用列（比如拿一个的 test 去比另一个的 valid），会得出完全反向的结论。

> 注意：这个例子是**方法论示例**——主日志是旧实现、E0 是新实现，两者**不是同一模型**，
> 所以上表的正负号**不能当性能结论**，只能用来演示"混列会出错"。

### 1.2 `param_check` 为什么是硬闸

E0 的参数 16,532,562 是 `d=624` 下 `exp=4, lin=1`（5 层）的**唯一理论值**（见 `参数量口径纪律` 文档）。
若实测不是这个数，可能原因只有三种：
1. 配置没生效（读错 yaml / expid 拼错）；
2. 代码被改动（结构变了）；
3. feature_map 不同（vocab 总和 ≠ 910,747）。

**三种都是致命的，必须先查清再继续跑其余种子**，否则 8 个种子全废。

## 二、汇总区（`section=summary`）

| key | 含义 | 算法 |
|---|---|---|
| `n_seeds` | 实际完成种子数 | 计 `status=ok` 的行数 |
| `valid_auc_mean` | valid AUC 均值 | 算术平均 |
| `valid_auc_sd` | **实测 σ（valid）** | 样本标准差，**ddof=1** |
| `valid_auc_ci95` | 95% CI 半宽 | `1.96 × sd / √n` |
| `test_auc_mean` | test AUC 均值 | ★**与作者基准比这个** |
| `test_auc_sd` | 实测 σ（test） | ddof=1 |
| `test_auc_ci95` | test 的 95% CI 半宽 | 同上 |
| `valid_logloss_mean` / `test_logloss_mean` | logloss 均值 | 分列 |
| `meas_sigma_valid` / `meas_sigma_test` | **实测 σ** | ← **功率分析要用这行** |
| `author_valid_auc` / `author_test_auc` | 作者基准（只读） | 0.815627 / 0.816145 |
| `dev_valid_abs` / `dev_test_abs` | 与作者的绝对偏差 | `|ours − author|`，**同列比** |
| `dev_valid_in_sigma` / `dev_test_in_sigma` | 偏差是否在 1σ 内 | `dev ≤ sd` → YES |
| `dev_verdict` | **是否复现成功** | 见 §2.1 |
| `epoch_sec_ours` | 我们的每轮秒数 | 与作者 204.365 s 比 |

### 2.1 「复现成功」的判据（写死，避免事后改口）

```
复现成功 ⟺  n_params == 16,532,562（精确相等）
           且 |valid_auc_mean − 0.815627| ≤ 1σ_valid
           且 |test_auc_mean  − 0.816145| ≤ 1σ_test
```

**三条全满足才算复现成功。**
若参数对但 AUC 偏差 > 1σ → 需先排除「数据管道不同」（查 vocab 总和是否 910,747），再下结论。
**不允许**先看 AUC 再看参数——参数是确定性的，AUC 是随机的，先看硬的。

### 2.2 与作者基准的比例参照

作者只跑了 **1 次**（seed=2025），所以「作者 σ」未知。
**因此我们只能用「我们的 σ」去衡量偏差**，并在报告里说明：

> 作者仅报告单次运行结果，未给出种子方差；本文以其单次结果为中心值，
> 用我们自己的 8 种子 σ 衡量偏差是否可分辨。这是本实验条件下能做到的最严格对照。

## 三、功率分析区（`section=power`）★ 报告加分点

### 3.1 公式

配对 t 检验（正态近似），每组所需样本量：

```
n = ( z_{1−α/2} + z_{power} )² · σ² / δ²
  = ( 1.959964 + 0.841621 )² · σ² / δ²
  = 7.849 · σ² / δ²
```

等价地，**给定 n 和 σ，本实验能分辨的最小效应**：

```
δ_min = (1.959964 + 0.841621) · σ / √n  =  2.801585 · σ / √n
```

### 3.2 预演：不同 σ 假设下所需配对种子数

| σ（假设） | δ=0.0005 | δ=0.0008 | δ=0.001 | δ=0.002 | δ=0.003 |
|---|---|---|---|---|---|
| 0.0005 | 8 | 4 | 2 | 1 | 1 |
| **0.001**（原规划值） | **32** | **13** | **8** | 2 | 1 |
| 0.0017（子集，**不可用**） | 91 | 36 | 23 | 6 | 3 |
| 0.002 | 126 | 50 | 32 | 8 | 4 |
| 0.003 | 283 | 111 | 71 | 18 | 8 |

**这三个粗体数（32 / 13 / 8）与 `docs/参考基准.md` §5.4 完全一致**，说明两处计算口径相同。

> ⚠️ **σ=0.0017 是子集实测值，不可用。** 子集只有约 20 万行，样本量太少，
> 方差估计本身不稳定（且与全量 3667 万行的分布不同）。
> **必须等 E0 全量 8 种子跑完，用实测 σ 替换后再定稿本表。**

### 3.3 「本次实验的分辨率」——必须写进报告的一句话

这是 captain 特别强调的一项，也是绝大多数复现报告缺失的部分。

模板（`e0_template.json` 的 `resolution_statement_template`）：

> 本次实验用 **{n}** 个配对种子。以实测 σ = **{sigma}** 计，在 α=0.05、power=0.80 下，
> 本实验能分辨的**最小效应**为 δ_min = 2.8016 × σ / √n = **{dmin}**。
> 因此 ΔAUC < {dmin} 的差异**本实验无法分辨**，不据此宣称改进有效。

### 3.4 常用组合的 δ_min（便于直接引用）

| n（配对种子） | σ=0.001 | σ=0.0008 | σ=0.0015 |
|---|---|---|---|
| 5 | 0.001253 | 0.001002 | 0.001879 |
| **8** | **0.000991** | **0.000792** | **0.001486** |
| 13 | 0.000777 | 0.000622 | 0.001166 |
| 16 | 0.000700 | 0.000560 | 0.001051 |

**读法**：若我们跑 8 个配对种子、实测 σ=0.001，则本实验的分辨率是 **0.000991**——
**凡是小于 0.00099 的改进，本实验一律测不出来**，报告必须如实这样说。

> 这正是 captain 把主贡献从 Tri-BCE 改成 LCA 的定量依据：
> Tri-BCE 整个组件的贡献只有 0.0008（论文 Table 4），**小于我们 8 种子的分辨率 0.000991**。
> 硬要做，得 **13 对种子**（`ceil(7.849 × 0.001² / 0.0008²)` = 13），约 33 小时。

### 3.5 与「统计不显著」的正确措辞

若 ΔAUC < δ_min：

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| 「改进无效」 | 「**未观察到可分辨差异**」 |
| 「证明没有提升」 | 「本实验条件下分辨率不足，无法判定」 |
| 「有提升趋势但不显著」 | （删掉——趋势不是结论） |

学术上这叫 **absence of evidence ≠ evidence of absence**（没找到证据 ≠ 证明不存在）。
这个区分在报告里点出来，是很明显的加分点。

## 四、填表流程（runner 照做）

```
1. 跑 seed 2025 → 填 detail 第 1 行 → 立刻检查 param_check
   ├─ MISMATCH → 停下！查配置/代码/feature_map，不要继续跑
   └─ OK → 继续
2. 重复跑完 8 个种子
3. 算 summary 区（mean / sd(ddof=1) / ci95）
4. 用实测 σ 重算 power 区
5. 写出 §3.3 那句话
```

**第 1 步的检查点最关键**：先跑 1 个种子验证配置，比跑完 8 个再发现参数错要好 8 倍。
