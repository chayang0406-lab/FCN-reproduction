# 论文正文与作者代码在预处理上不一致（2026-11-18，captain 实测发现）

> 这是一个**纯技术核算**就能确认的硬发现，不依赖硬件、不依赖随机性。
> 报告「与原文工作的对比分析」一节可以直接用它，是理解深度的体现。

## 一、发现：I 字段的离散化规则，论文写的和代码做的不一样

### 论文正文（§6.1.2 Data Preprocessing）原话
> "For the Criteo and KDD12 dataset, we discretize the numerical feature fields
> by rounding down each numeric value 𝑥 to **⌊log2(𝑥)⌋** if 𝑥>2, and 𝑥=1 otherwise."

### 作者代码（`reczoo/Datasets` 与 fuxictr 1/2 版一致）
```python
def _convert_to_bucket(value):
    if value > 2:
        value = int(np.floor(np.log(value) ** 2))   # ← (ln x)^2，不是 log2(x)
    else:
        value = int(value)
    return value
```
注意：`np.log` 是**自然对数**，`**2` 是**平方**。所以实现的是 **⌊(ln x)²⌋**。

## 二、用真实数据判定：代码是对的，论文正文写错了

我用 Criteo 前 20 万行实测两种规则的取值个数，与作者日志的 `vocab_size` 对照：

| 字段 | 用 `⌊(ln x)²⌋`（代码） | 用 `⌊log2 x⌋`（论文正文） | 作者日志 vocab |
|---|---|---|---|
| I1 | 36 | **10** | **44** |
| I2 | 88 | **16** | **99** |
| I3 | 86 | **16** | **122** |
| I4 | 28 | **9** | **41** |
| I13 | 46 | **12** | **72** |

> ⚠️ **修正记录（2026-11-18，writer 复核后纠正 captain）**
> 上表「`⌊(ln x)²⌋`」这一列是**从 20 万行子集中实际数出来的桶数，不是由最大值反解的上界**。
> 因为子集最大值低估了全量最大值（例如 I9 子集 max=7,874，全量必然更大），
> 这一列的个别值（I9=81、I13=69）反而**小于**作者 vocab（92、72），
> 作为「上界」在逻辑上不成立。**不能拿这一列当论据。**
>
> 正确的论证方式见下方第二节修订版（只由 max 反解「所需最大 x」）。

## 二（修订版）、决定性论证：用「所需的 x 最大值」反解

先把 vocab 与桶数的换算钉住：
```
vocab_size = 真实桶数 k + 2      # padding_idx=0 与 oov_idx 各占一位
```
验证：作者日志 `C1: vocab_size=1446, oov_idx=1445` → k = 1444，+2 = 1446 ✓

于是若某字段的 vocab 为 V，则它至少需要 `k = V − 2` 个不同桶。
而 `⌊log2 x⌋` 在 `x ≤ x_max` 时最多给出 `⌊log2(x_max)⌋ + 1` 个桶，
故要满足需求必须 `x_max ≥ 2^(V−3)`。

| 字段 | 子集实测 max | 作者 vocab V | 需要的桶 k=V−2 | log₂ 规则要求的 x_max | 与实测 max 的差距 |
|---|---|---|---|---|---|
| I1 | 780 | 44 | 42 | 2^41 ≈ 2.20×10¹² | **2.8×10⁹ 倍** |
| I3 | 65,535 | 122 | 120 | 2^119 ≈ 6.65×10³⁵ | **1.0×10³¹ 倍** |
| I5 | 2,295,404 | 220 | 218 | 2^217 ≈ 2.11×10⁶⁵ | **9.2×10⁵⁸ 倍** |
| I9 | 7,874 | 92 | 90 | 2^89 ≈ 6.19×10²⁶ | **7.9×10²² 倍** |
| I13 | 3,890 | 72 | 70 | 2^69 ≈ 5.90×10²⁰ | **1.5×10¹⁷ 倍** |

**Criteo 的普通整数字段不可能达到 10¹² 以上的量级**，故 `⌊log2 x⌋` 被排除。
而被排除的 12 个字段里，差距**最小**的 I11 也要求 x_max ≥ 1.68×10⁷（实测 119，差 14 万倍）。

### ⚠️ 诚实的例外：I10 **无法**判别（所以是 12/13，不是 13/13）

| 字段 | 子集 max | 作者 vocab V | 需要 k | log₂ 在 x≤max 时的桶数 | 判定 |
|---|---|---|---|---|---|
| **I10** | **8** | **6** | **4** | **{0,1,2,3} = 4 个** | **恰好够用，无法排除** |

`⌊log2 x⌋` 在 `x ≤ 8` 时给出 4 个桶，正好满足 I10 需要的 4 个，**边界上刚好够**。
即使全量数据里 I10 的最大值更大（比如 16 → 5 个桶），也只会更多、不会更少，**仍然排除不了**。

**所以正确表述是「12 个字段决定性排除 + 1 个（I10）无法判别」，不能凑成 13/13。**
（这一处是 writer 复核后纠正我的，原文我写成了 13/13。）

## 三、这个发现的意义（报告里怎么用）

### 1. 它证明了我们的数据管道是**与作者代码**对齐的，不是盲从论文文字
报告可以写：
> 「论文正文称数值特征按 ⌊log2(x)⌋ 离散化，但经实测核对，作者开源代码与其日志中
> 各字段的 vocab_size 只能由 ⌊(ln x)²⌋ 生成：以 I1 为例，⌊log2(x)⌋ 在 Criteo 的取值范围内
> 最多产生 19 个不同取值，而作者日志记录的 vocab_size 为 44，故实际实现必为 ⌊(ln x)²⌋。
> 本文以作者代码为准。」

这段话的价值：**说明我们不是照着论文抄，而是核对了论文、代码、日志三者的一致性。**

### 2. 它是一个「论文可复现性」的具体案例
摘要/引言里我们想说的「复现论文需要核对多处细节」不再空泛，
有一个可以摆出来的、有数学上界的硬证据。

### 3. 它提醒：不要用论文文字去改代码
如果有人"按论文修正"成 `log2`，会导致 vocab 从 44 掉到 12 左右，
**整个数据管道与作者不一致，复现必然失败**。这是个真实的陷阱。

## 四、另一个实测发现：I 字段有大量空值

| 字段 | 空串比例 |
|---|---|
| I1 | **42.49%** |
| I3 | 22.70% |
| I4 | 23.78% |
| I13 | 23.78% |
| I2 | 0% |

**含义**：
1. 数据集配置里必须保留 `fill_na: 0` / `na_value: 0`（作者配置里确实有），
   把空值填成 0，再走 bucketize（0 ≤ 2 所以归到 0 桶）。
2. 这也解释了为什么 I1 的 vocab 只有 44——很多值被填成 0 后进同一个桶。
3. **验证管道正确性的一个额外检查**：如果 `fill_na` 没生效，
   I1 的 vocab 会明显偏离 44。

## 五、对 t4 验收的影响（已确认我们的实现是对的）

`tools/build_h5.py` 用的是 `fuxictr.datasets.criteo.FeatureProcessor`，
即作者的 `⌊(ln x)²⌋` 实现 —— **正确**。
配合 `feature_cols` 里的 `fill_na: 0`、`min_categr_count: 10`，
全量数据跑完应得到：
- Σ(vocab_size) = **910,747**
- I1=44, I2=99, I3=122, I4=41, I13=72 …（作者日志全表）

**如果 t4 跑出来 I1 的 vocab 是 12 而不是 44，说明 bucketize 用错了（用了 log2），必须查。**

## 六、C 字段的过滤逻辑（顺带核实）

| 字段 | 原始不同取值 | 过滤 ≥10 次后 | 作者日志 |
|---|---|---|---|
| C1 | 712 | 143 | 1446 |
| C2 | 513 | 422 | 554 |
| C14 | 26 | 25 | 28 |
| C17 | 10 | 9 | 12 |

**注意**：子集（20 万行）的过滤后取值数**必然小于**全量（3670 万行），
因为同一取值在子集里出现次数少、更容易被过滤掉。
所以这些数**不能**用来判定对错，只能在全量数据上验证。
（这与 data 提出的「原始基数 vs 过滤后 vocab」区分是同一个问题，他提得对。）

`vocab_size = 过滤后不同取值数 + 2`（padding_idx=0 与 oov_idx 各占一位，
从作者日志 `C1: vocab_size 1446, oov_idx 1445` 可确认这个关系）。
