# 依赖与兼容性实测结论（2026-11-18，captain 亲自跑出来）

> 目的：把「环境能不能装」这个最大不确定项提前钉死，避免团队反复试错。
> 所有结论都是在本机 Python 3.11 + fuxictr 2.0.1 真实运行时得出的，不是查文档推测。

## 一、必需的依赖版本（按此安装）

| 包 | 版本 | 原因 |
|---|---|---|
| `scikit-learn` | **==1.4.2** | 见下方第一节「最关键的坑」。**不能 ≥1.5.0** |
| `h5py` | 3.14.0 | 实测可用 |
| `fuxictr` | **==2.0.1** | 论文强制要求，换版本结果不可比 |
| `PyYAML` | 6.0.3 | |
| `keras_preprocessing` | 1.1.2 | |
| `polars` | 1.x | 仓库 requirements 写 `polars<=1.0.0` |
| `numpy` | **1.25.0，不要动** | 服务器平台 torch 2.7.1+das.opt1.dtk2604 依赖它 |
| `pandas` | 服务器已是 2.3.3，可直接用 | |

## 二、最关键的坑：sklearn 版本边界在 1.5.0

fuxictr 2.0.1 的 `metrics.py:30` 调用：

```python
return_dict[metric] = log_loss(y_true, y_pred, eps=1e-7)
```

`log_loss` 的 `eps` 参数在 **scikit-learn 1.5.0 被删除**。实测签名对照：

| sklearn 版本 | `log_loss` 签名 | 能否跑 |
|---|---|---|
| 1.2.2 | `(y_true, y_pred, *, eps="auto", ...)` | ✅ |
| 1.3.2 | 同上 | ✅ |
| 1.4.2 | 同上 | ✅ |
| **1.5.0 / 1.5.1 / 1.5.2** | `(y_true, y_pred, *, normalize=..., ...)` | ❌ 无 eps |
| 1.7.2 | 同上 | ❌ |

报错长相：
```
TypeError: got an unexpected keyword argument 'eps'
```

**结论：装 `scikit-learn==1.4.2`。** 官方有 `cp311-manylinux2014_x86_64` 轮子（12,146,964 字节），
且它要求 `numpy>=1.19.5`，与服务器 numpy 1.25.0 完全兼容 —— 不需要动 numpy。

> 这条如果没提前发现，症状是「模型训练第一个 epoch 结束、算指标时才崩」，
> 会让人误以为是数据问题或 DCU 问题，排查方向全错。这是本项目最大的时间陷阱。

## 三、官方 `run_expid.py` 自身的 bug（必须改）

仓库 `run_expid.py` 第 28–29 行：

```python
from fuxictr.preprocess import FeatureProcessor          # 通用版
from fuxictr.datasets.kkbox import FeatureProcessor      # ← 立刻把上一行覆盖掉
```

KKBox 版 `FeatureProcessor` 只有 `extract_country_code` / `bucketize_age`，**没有 `convert_to_bucket`**；
而 Criteo 的字段配置（`config/dataset_config.yaml` 里的 `Criteo_x4_001`）要求 13 个 I 字段走
`convert_to_bucket`。于是 CSV→h5 阶段必然报：

```
AttributeError: 'FeatureProcessor' object has no attribute 'convert_to_bucket'
```

**作者自己没踩到**，因为他的日志里 `data_format: h5` —— 直接用别人转换好的 h5，跳过了这一步。

**修法**：Criteo 必须用
```python
from fuxictr.datasets.criteo import FeatureProcessor
```

这属于「为适配运行环境所做的必要修改」，应写进报告附录（诚实、可核查的工作量）。

## 四、`src/__init__.py` 的连带依赖

```python
from .ECN import *
from .ECN_full import *
from .FCNv1 import *
from .FCNv1_full import *
from .LCN import *
from .FCNv2 import *
```

只拷 `FCNv2.py` 会 `ModuleNotFoundError`。必须把这 5 个 `.py` 一起拷。
（`LCN_full.py` 在仓库中不存在，但 `__init__` 未引用，无需处理。）

## 五、本机与服务器的差异（别把本机的坑带过去）

| 问题 | 本机 | 服务器 | 处理 |
|---|---|---|---|
| `np.Inf`（numpy 2.0 已移除） | 会报错（本机 numpy 2.x） | **不会**（numpy 固定 1.25.0） | 本机临时补 `np.Inf = np.inf`，服务器无需改 |
| `log_loss(eps=)` | 会报错（装了 sklearn 1.7.2） | 取决于装哪个版本 | **两边都必须装 sklearn 1.4.2** |

## 六、已验证跑通的证明

`tools/smoke_local_fcnv2.py`（本机 CPU + 合成 4000 条数据）实测：
- CSV → h5 转换成功，生成 train.h5 / valid.h5 / test.h5
- feature_map.json 正常产出
- FCNv2 模型构建成功，参数量 = 1,208,210（合成数据口径，非真实数据）
- 训练循环进入并跑完 batch，卡在指标计算（即 sklearn eps 那个坑）

**说明：除 sklearn 版本外，整条链路（数据转换 → 建模 → 前向 → 反向 → 评估）是通的。**

## 七、离线安装命令（服务器无外网，只能这样装）

本地下载（Windows，py -3 或任一 Python 3.11）：
```powershell
py -3 -m pip download --only-binary=:all: `
  --platform manylinux2014_x86_64 --python-version 311 `
  --implementation cp --abi cp311 -d .\wheels `
  scikit-learn==1.4.2 h5py==3.14.0 PyYAML keras_preprocessing polars tqdm joblib
```

上传后在服务器：
```bash
/usr/local/bin/python3 -m pip install --no-index --find-links=/path/to/wheels \
  scikit-learn==1.4.2 h5py==3.14.0 PyYAML keras_preprocessing polars
```

注意：**不要 `pip install -U numpy`**，会把平台 torch 弄崩。
