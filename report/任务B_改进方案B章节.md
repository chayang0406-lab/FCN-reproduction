## 3.5.2 改进方案 B 设计：BSW-Tri 有界软权重

### 3.5.2.1 先说清楚我们要改什么

论文的 Tri-BCE 是这样一个设计：模型里有两条"腿"——一条抓高阶特征组合（ECN），
一条抓低阶组合（LCN）——最后拼起来出结果。普通做法只看拼起来的结果算一次损失
（loss，可以理解为"预测错得有多离谱"的分数）。Tri-BCE 的做法是**再多算两次**：
让 ECN 单独出一次预测、LCN 单独出一次预测，各自和真实标签比一次，得到两个"辅助损失"。

**关键在那个"怎么给辅助损失加权"上**，作者写的是：

```
w_exp = max(0, L_exp − L)
w_lin = max(0, L_lin − L)
```

其中 `L` 是主损失（整体预测的错），`L_exp` / `L_lin` 是两条腿各自的损失。

**人话**：只有某条腿比整体表现更差（损失更大）时，才给它权重，让它加把劲；
如果它比整体还好，权重就是 0，不管它。

这个直觉是对的。但**具体的函数形式有三个毛病**，我们逐个说。

### 3.5.2.2 原版权重函数的两个真实缺陷

#### 缺陷一：权重没有上界

`max(0, Δ)` 是**线性增长**的——Δ（两条损失的差）翻倍，权重就翻倍，没有封顶。

**这为什么是问题**？看训练初期的实际数字：

| 训练阶段 | 主损失 L | 若 Δ = 0.5 |
|---|---|---|
| 刚开始（参数随机） | 约 0.693 | 权重 = 0.5 |
| 收敛后（E0 实测） | 约 0.437 | 权重 = 0.5 |

在收敛后，主损失本身只有 0.437，而辅助权重 0.5 比它还大。此时总损失是

```
L_total = L + w·L_aux = 0.437 + 0.5 × L_aux
```

**辅助项占了总损失的一半以上**，模型的优化目标被辅助任务带偏了——
本来该学"整体预测准"，变成了"学两条腿各自准"。

**打个比方**：小组作业按总分排名，但老师说"谁的单项分比总分低得多，就把他的单项分乘个系数加进来"。
如果这个系数大到超过总分本身，那大家就只顾刷单项分了。

#### 缺陷二：在 Δ = 0 处梯度跳变

`max(0, x)` 在 x < 0 时恒为 0，导数也是 0；在 x > 0 时导数突然变成 1。
**这一点上导数不连续**（数学上叫"不可导"）。

**打比方**：开车时油门踩下去 0.9 厘米没反应，踩到 1.0 厘米突然全功率输出。
实际训练里这会带来数值不稳。

> **注**：这个缺陷的严重性弱于缺陷一。作者用的 `max(0, ·)` 在 Δ=0 这一点不可导，
> 但在实际训练中 Δ 恰好精确等于 0 的概率极低（浮点数），
> 所以它更多是"理论上的不优雅"，而不是"实践中会炸"。
> **我们如实标注这一点，不夸大它的危害。**

### 3.5.2.3 一个必须先讲清的数学事实：四个性质不能同时满足

设计新权重函数时，我们希望它同时满足四条：

| 编号 | 性质 | 为什么想要 |
|---|---|---|
| **C1** | Δ ≤ 0 时 w = 0 | 与作者语义一致：学得好的腿不奖不罚 |
| **C2** | w 随 Δ 单调递增 | 差得越多，给的权重越大 |
| **C3** | w 有上界 | 修掉缺陷一 |
| **C4** | w 处处可导 | 修掉缺陷二 |

**结论：这四条互不相容，必须放弃至少一条。**

**证明**（三行）：

1. 由 C1，对所有 x ≤ 0 有 f(x) = 0，所以左导数 f′(0⁻) = 0。
2. 由 C4，左右导数必须相等，故要求 f′(0⁺) = 0。
3. 但由 C2（严格递增），f′(0⁺) 应当大于 0。矛盾。

**人话**：你要求这个函数在 0 的左边一直是平的（高度 0），又要求它在 0 处平滑过渡，
还要求它在 0 右边立刻往上走——**这三件事凑不到一起**。要么 0 处有个折角（放弃 C4），
要么 0 左边不是平的（放弃 C1）。

> **这个结论值得单独写出来**，因为它解释了"为什么我们没有一个完美方案"——
> 不是我们没想到，而是**数学上不存在**。任何声称同时做到这四点的方案，
> 要么偷偷放弃了某条，要么在定义上做了文字游戏。

### 3.5.2.4 我们的选择与最终形式

**决定放弃 C4（处处可导），保留 C1（语义一致），补上 C3（有界）**。

理由：C1 是作者设计的**语义核心**（"只惩罚差的腿"），改了它就不是同一个方法了；
而 C4 在实践中影响有限（见 3.5.2.2 的注）。C3 是我们要修的真问题。

最终形式：

```
w = α · tanh( β · relu(Δ) / L )
```

其中 `relu(x) = max(0, x)`（整流，负数一律变 0），`tanh` 是双曲正切函数。

**逐项解释**：

| 组成部分 | 作用 | 对应的改进 |
|---|---|---|
| `relu(Δ)` | Δ ≤ 0 时整项为 0 | 保留 C1，与作者语义一致 |
| `tanh(·)` | 输出被限制在 (−1, 1)，乘 α 后上界为 α | **修掉缺陷一** |
| `÷ L` | 用"相对差"而不是"绝对差" | 跨数据集、跨训练阶段可比 |
| `α`（超参） | 权重上界 | 可调 |
| `β`（超参） | 饱和的速度 | 可调 |

**人话**：先按作者的意思判断"这条腿是不是更差"（relu），如果是，
就按"差了多少比例"（除以 L）给权重，但**最多给到 α 那么多**（tanh 封顶）。

**为什么 `tanh` 而不是别的**：`tanh(x)` 在 x 很小时约等于 x（线性），
在 x 很大时趋近 1（饱和）。这正好是"小差距按比例给、大差距封顶"的形状，
而且它本身是光滑的。

### 3.5.2.5 β 的标定：怎么让改进"不改变原始行为"

新方案有个风险：**万一它一开始就和作者差太远，我们测到的就不是"改进"而是"换了个方法"**。

所以要先把 β 标定到"小差距时与作者几乎一致"。

**推导**：`tanh(x) ≈ x` 当 x → 0，所以

```
w = α · tanh(β·Δ/L) ≈ α · β · Δ / L        （Δ 较小时）
```

要与作者的 `w = Δ` 对齐，需要 `α·β/L ≈ 1`，即 **β ≈ L / α**。

E0 实测主损失稳定在 **L ≈ 0.437**，α = 1 时 **β ≈ 0.44**。取 **β = 0.45**。

**实测验证这张表**（这是我实际跑出来的数，不是推的）：

| Δ | 作者 `max(0,Δ)` | BSW（β=0.45） | 相对误差 |
|---|---|---|---|
| 0.01 | 0.010000 | 0.010000 | 0.0% |
| 0.05 | 0.050000 | **0.049958** | **0.1%** |
| 0.10 | 0.100000 | 0.099668 | 0.3% |
| 0.30 | 0.300000 | 0.291313 | 2.9% |
| 0.50 | 0.500000 | 0.462117 | 7.6% |
| 1.00 | 1.000000 | 0.761594 | 23.8% |
| 5.00 | 5.000000 | **0.999909** | **80.0%**（封顶） |

**读法**：
- Δ ≤ 0.1（绝大多数情况）：与作者差 0.3% 以内，**几乎是同一个方法**
- Δ 很大（≥ 1.0）：作者给 1.0 甚至 5.0 的权重，我们封顶在 1.0 以内

**所以这个改进是"只在极端情况下起作用"的**——这正是"温和改进"该有的样子，
也意味着**它的效果可能很小**（见 3.6 的效应量分析，我们如实标注了这个风险）。

### 3.5.2.6 与已有软化方案的关系

项目代码里原本已有三种软化模式（由方案 A 一侧实现），加上我们的方案，对比如下：

| 方案 | 权重函数 | 非负 | 有上界 | 尺度归一 |
|---|---|---|---|---|
| 作者 hard | `max(0, Δ)` | ✅ | ❌ | ❌ |
| softplus | `α·softplus(βΔ)/β` | ✅ | ❌ | ❌ |
| smoothmax | `α·Δ·sigmoid(βΔ)` | ✅ | ❌ | ❌ |
| ratio | `α·Δ/(L_aux+L)` | ❌ 可为负 | ❌ | ✅ |
| **BSW-Tri（本文）** | `α·tanh(β·relu(Δ)/L)` | ✅ | **✅** | **✅** |

**关键差异**：前三种都**没有上界**（softplus 和 smoothmax 当 Δ→∞ 时线性发散，
ratio 当 Δ→∞ 时趋近 α 但分母含 L_aux 会抖动）。**只有 BSW-Tri 三项齐全。**

> **一处必须说清的边界**：`ratio` 模式在 Δ<0 时会给出负权重，
> 而负权重意味着"优化器会主动抬高这条腿的损失"，语义上是错的。
> 我们没改它（那是方案 A 的代码，不越界），但在这里标注出来，
> 避免后续有人误用。

## 3.6 改进方案 B 的消融与参数实验设计

### 3.6.1 设计目标：证明"每个组件都真的有用"

一个新方案要站得住，必须回答三个问题：

1. **它比原版好吗**？（主实验，对比 hard）
2. **好在哪个组件上**？（消融：去掉某个组件会怎样）
3. **换个参数还成立吗**？（敏感性：β 和 α 变动时结论是否稳定）

**这三个问题对应三组实验，缺一组就有"碰巧调对了"的嫌疑。**

### 3.6.2 消融矩阵（6 个配置）

| 编号 | expid | 权重形式 | 参数量 | 回答什么问题 |
|---|---|---|---|---|
| **A1** | `FCNv2_C_base` | 作者 hard | 16,532,562 | **对照基线** |
| **A2** | `FCNv2_C_bsw_b045` | BSW β=0.45 | 16,532,562 | **完整方案是否更好** |
| **A3** | `FCNv2_C_bsw_b100` | BSW β=1.0 | 16,532,562 | β 变大（权重放大 2.2 倍）是否影响 |
| **A4** | `FCNv2_C_bsw_abs` | BSW 去掉 `÷L` | 16,532,562 | **"尺度归一"这一项有没有贡献** |
| **A5** | `FCNv2_C_bsw_a10` | BSW α=10 | 16,532,562 | **"有界性"这一项有没有贡献** |
| **A6** | `FCNv2_C_bsw_plain` | 无 Tri-BCE | 16,532,562 | Tri-BCE 本身有没有用 |

**六者参数量完全相同（16,532,562）**——这一点我实际实例化模型验证过，
不是从配置推的。**这意味着任何精度差异都不能用"参数多所以强"来解释。**

#### 每一组的设计意图

**A2 vs A1（主实验）**
回答"完整方案比作者好吗"。β=0.45 已标定到"小 Δ 区与作者差 0.1%"，
所以这个对比是**最小改动下的纯净对比**。

**A4 vs A2（去掉尺度归一）**
A4 把 `÷L` 换成除以常数，变成"绝对差 + 有界"。
若 A2 优于 A4，说明"用相对差"这个设计有贡献；
若两者无差别，说明**尺度归一这一项是多余的**——这同样是有效结论，我们会如实报告。

**A5 vs A2（放大上界）**
A5 把 α 从 1.0 放大到 10.0，tanh 的饱和点被推到很远，**行为接近"无界"**。
若 A5 明显差于 A2，说明"有界性"确实重要；
若 A5 ≈ A2，说明**实际训练中权重根本没到饱和区**，那么"有界"这个改进在实践中无用，
**我们也会如实说**。

**A6 vs A1（无 Tri-BCE）**
这是复现论文 Table 4 的消融（论文报告 Tri-BCE 总计贡献约 0.08 个百分点）。
**这一组是我们判断"实验分辨率够不够"的标尺**：如果连论文报告的 0.08pp 都测不出来，
那我们的改进（预计更小）就必然测不出来。

**A3 vs A2（β 敏感性）**
β 从 0.45 到 1.0，等于把权重整体放大 2.2 倍。
若两者接近，说明方案对 β 不敏感（好事，鲁棒）；
若差别明显，说明 β 需要调参（这是另一个可写的结论）。

### 3.6.3 为什么必须 8 个种子

这是本项目最重要的方法论前提，必须写清楚。

**问题**：CTR 模型之间的真实差距非常小。论文原文有两处关键表述：

> FCN achieves the best performance across all six datasets, with an **average AUC
> improvement of 0.25%** over the strongest baseline model and an average Logloss
> decrease of 0.19%, both exceeding the **statistically significant threshold of 0.1%**.

> **Typically, CTR researchers consider an improvement of 0.001 (0.1%) in Logloss and
> AUC to be statistically significant** [2, 40, 42, 56].

**人话**：作者自己给的判据是——**AUC 或 Logloss 提升 0.001 才算"显著"**。
而它比最强基线平均只好 0.25 个百分点。**也就是说，真正要比的量级是 0.1–0.3 个百分点。**

而**同一个模型换个随机种子重跑，结果会波动**。所以"跑出 81.6 比 81.5 高"这句话，
**在不知道波动幅度时完全没有信息量**。

> **这个 0.001 的门槛给我们提供了一个外部标尺**：
> 若我们能测出的 δ_min 大于 0.001，说明**我们的实验连论文自己的显著性标准都达不到**，
> 那么任何"改进有效"的结论都不可信。这一条会写进 5.5 的结论里。

**打个比方**：两个射手，一个打 81.6 环、一个打 81.5 环。
如果每个人每次都在 81.0–82.0 之间晃，那这 0.1 环的差距就是噪声；
如果每次只晃 0.01 环，那 0.1 环就是真本事。**不测波动，就没法判断。**

**计算方法**：要用配对设计的 t 检验分辨出差异 δ，所需配对数

```
n = (t_{0.975} + t_{0.80})² · σ² / δ² = 7.849 · σ² / δ²
```

（`t_{0.975}=1.960` 是"假阳性率 5%"的分位数，`t_{0.80}=0.842` 是"检出率 80%"的分位数，
两者之和 2.8016，平方得 7.849。）

**8 个种子能分辨多大的差异**：把 n=8 代回去反解

```
δ_min = 2.8016 · σ / √8 = 0.9905 · σ
```

**人话**：8 个配对种子，能测出的最小差异约等于"1 个标准差"。

**这张表要这么读**——把论文自己的门槛代进去：

| 若种子噪声 σ = | 8 种子能分辨 δ_min | 能否达到论文的 0.001 门槛 |
|---|---|---|
| 1e-4 | 9.9e-5 ≈ 0.01pp | 能 |
| 2e-4 | 2.0e-4 ≈ 0.02pp | 能 |
| 5e-4 | 4.95e-4 ≈ 0.05pp | 能 |
| **1.01e-3（临界值）** | **1.0e-3 ≈ 0.10pp** | **刚好卡线** |
| 2e-3 | 1.98e-3 ≈ 0.20pp | **不能** |

**临界点算出来是 σ = 1.01e-3**（由 `δ√n/k = 0.001×√8/2.8016` 得到）。

**人话**：8 个种子刚好能撑住论文那个 0.001 的显著性门槛——
**但前提是种子噪声不超过 0.001。再大就不够了。**

**这对我们的改进意味着什么**（必须提前说清）：

论文 Table 4 显示 **Tri-BCE 整体的贡献是 0.08 个百分点（8e-4）**。
我们的 BSW 是在 Tri-BCE **内部**再改权重函数，**效应必然小于 8e-4**。

- 若实测 σ ≈ 5e-4 → δ_min ≈ 4.95e-4，理论上勉强能测到 8e-4 量级
- 若实测 σ ≈ 1e-3 → δ_min ≈ 9.9e-4 > 8e-4，**连论文自己的消融都测不出来**，
  我们的改进更测不出来

> **这个风险我们不隐藏**：BSW-Tri 是一个"只在极端 Δ 才生效"的改动（见 3.5.2.5 的表），
> 效应量预计很小。**若实测测不出，我们会如实报告"在本实验分辨率下不可分辨"，
> 而不是挑一个种子报好看的数字。** 这也是本项目把多种子配对设计作为前提的原因——
> 它让我们**有能力诚实地承认"测不出来"**。

### 3.6.4 参数敏感性实验

β 和 α 各扫三个点，组成 3×3 网格中的一部分（受机时限制，只做对角线与关键点）：

| 配置 | β | α | 目的 |
|---|---|---|---|
| bsw_b045 | 0.45 | 1.0 | 主实验（与作者尺度对齐） |
| bsw_b100 | 1.0 | 1.0 | β 敏感性 |
| bsw_a10 | 0.45 | 10.0 | α 敏感性（近似无界） |
| bsw_b045_a3 | 0.45 | 3.0 | 中间点（`待补·E3`，视机时决定是否补） |

**判据**：若 β 在 [0.45, 1.0]、α 在 [1, 10] 内结论方向不变，
说明方案对超参不敏感，鲁棒性好；若方向翻转，则必须报出"仅在某个参数区间有效"。

### 3.6.5 资源开销分析设计

BSW-Tri 的额外开销只有一项：**损失计算里多两次 `tanh`**。

- **参数量**：+0（已实测确认，六个配置都是 16,532,562）
- **显存**：+0（`tanh` 是逐元素运算，不新增张量）
- **计算量**：+2 次 `tanh`（batch 级标量运算，相对前向/反向可忽略）
- **训练时间**：预期与基线相同（在 5.7 实测验证）

**对比方案 A（LCA 压缩率）**：那一个改动的是**模型结构**，参数量随 r 变化
（r=0.25 时 16,342,242，r=1 时 21,593,202），直接影响显存与推理延迟。

**所以两个方案的性质完全不同**：

| | 方案 A（LCA 压缩率） | 方案 B（BSW-Tri） |
|---|---|---|
| 改动位置 | 模型结构 | 损失函数 |
| 参数量 | **随 r 变化** | **不变** |
| 影响显存 | 是 | 否 |
| 影响推理延迟 | 是 | 否 |
| 预期效应量 | 较大（参数减半） | **较小（权重微调）** |

**这个对比本身就是 5.8 节要讨论的核心内容**——两个方案各自解决不同层面的问题，
不能简单地比"谁的 AUC 高"。

## 4.6.2 改进方案 B 的具体实现

### 4.6.2.1 代码位置与改动范围

全部改动集中在两个文件，**不改动作者原仓库任何一个字节**：

| 文件 | 改动 | 行数变化 |
|---|---|---|
| `code/src/fcn_v2_soft.py` | 新增 `bsw` 模式（5 处） | +40 行左右 |
| `code/configs/model_config.yaml` | 新增 5 个 expid | +130 行 |

### 4.6.2.2 五处改动逐项说明

#### 改动 1：注册新模式

```python
TRI_BCE_MODES = ("hard", "softplus", "smoothmax", "ratio", "bsw", "plain")
```

**为什么重要**：构造函数里有校验，模式名拼错会立刻报错，**不会静默退回原版**。
这条校验是方案 A 一侧早就加好的，我们复用它。

> **这个细节值得说明**：如果校验缺失，`tri_bce_mode="bsww"`（多打一个字母）
> 会静默走默认分支，跑出来的是原始 FCN，而报告里会写"BSW-Tri 无效"。
> **一个拼写错误就能毁掉整个结论**，所以这种校验必须存在。

#### 改动 2-3：新增超参与前向声明

在 `__init__` 里加一个布尔开关：

```python
tri_bce_bsw_relative=True      # True=用相对差（÷L），False=用绝对差（消融用）
```

并在属性赋值处保存。

#### 改动 4：权重计算分支（核心）

```python
elif self.tri_bce_mode == "bsw":
    beta = self.tri_bce_beta
    if beta <= 0:
        raise ValueError("tri_bce_beta 必须 > 0，收到 %r" % beta)
    positive = torch.clamp(delta, min=0.0)        # ① relu 整流
    if self.tri_bce_bsw_relative:
        denom = torch.clamp(loss_main, min=self.tri_bce_eps)
        arg = beta * positive / denom             # ② 尺度归一
    else:
        arg = beta * positive                     # 消融：绝对差
    w = self.tri_bce_alpha * torch.tanh(arg)      # ③ 有界饱和
```

三个 `torch.clamp` 的作用分别是：
- `clamp(delta, min=0)`：整流，Δ≤0 时归零
- `clamp(loss_main, min=eps)`：防止 L 趋近 0 时除零（BCE 恒正，正常情况下不起作用）

**为什么用 `torch.clamp` 而不是 Python 的 `max`**：
`max(0, tensor)` 在 PyTorch 里会丢掉梯度信息，而 `torch.clamp` 保留梯度。
这是实现上必须注意的一点。

#### 改动 5：文档字符串

在模块头部说明里补上 bsw 的定义，供后续查阅。

### 4.6.2.3 验证：三组检查

**光写完代码不算完成，必须证明它真的按设计工作。**

#### 检查一：数值性质（4 项）

| 检查 | 方法 | 实测结果 |
|---|---|---|
| Δ ≤ 0 时权重恒为 0 | 取 Δ ∈ {−1.0, −0.5, −0.1, −0.01} | 全部 = 0.0 ✅ |
| 权重有上界 | 取 Δ = 10⁶（极端值） | 0.999909 ≤ α ✅ |
| 单调递增 | Δ 从 0.01 到 5.0 | 单调上升 ✅ |
| β=0.45 时与作者接近 | Δ = 0.05，与 `max(0,Δ)` 比 | 差 0.1% ✅ |

#### 检查二：参数量不变（关键）

实际实例化 6 个配置的模型，数 `sum(p.numel() for p in model.parameters())`：

```

FCNv2_C_bsw_b045     bsw     16,532,562
FCNv2_C_bsw_b100     bsw     16,532,562
```

**六个值完全相等，且等于作者日志里的 16,532,562。**

逐项打印每个 expid 的 `tri_bce_mode` / `alpha` / `beta` / `bsw_relative`，确认与设计表一致。

### 4.6.2.4 实现过程中的一个真实教训

**首次写配置时出现了一次静默失败，值得记录。**

我用正则替换的方式生成新配置块：以现有的 `FCNv2_C_soft_smoothmax` 为模板，
逐字段替换。但模板里**没有** `tri_bce_bsw_relative` 这一行
（因为它是我们新加的参数），而 `re.sub` 对"找不到的模式"会**静默返回原文**——
不报错、不警告，配置块看起来完全正常，只是**少了这个字段**。

后果：`bsw_relative` 取默认值 `True`，
**导致 `FCNv2_C_bsw_abs`（本应验证"去掉尺度归一"）实际上和主实验完全一样**。
如果不检查，5.5 的消融结论会得出"尺度归一没有作用"——**一个完全错误的结论**。

**修复方式**：显式检查每个配置块内的字段是否齐全，缺失则插入，并逐项复验打印。

> **这条教训的一般形式**：`re.sub` / `dict.get` / `if exists: skip` 这类"找不到就沉默"
> 的写法，在**生成配置**时特别危险。因为配置生成的输出是"给人看的文本"，
> 少了字段肉眼看不出来，只有和设计表逐项对照才能发现。
> **本项目在数据转换、日志解析、进程清理上都栽过同类跟头**（详见方法论附录）。

### 4.6.2.5 与方案 A 实现的接口约定

两个方案共用同一个模型类 `FCNv2Soft`，各自控制不同的开关，互不干扰：

| 开关 | 所属 | 默认值 | 说明 |
|---|---|---|---|
| `lca_compress_ratio` | 方案 A | 0.5 | 改模型结构 |
| `tri_bce_mode` | 方案 B | "hard" | 改损失函数 |
| `tri_bce_bsw_relative` | 方案 B | True | 方案 B 专用 |

**默认值全部取"原版行为"**，所以任何一方单独开关都能保证另一方的行为不变。
这是两个改进可以放在同一份代码里、且能独立消融的前提。

> **一个具体的验证**：`FCNv2_C_base`（两个开关都取默认）的参数量 16,532,562
> 与作者日志精确相等，说明默认路径确实未被污染。
